## 本目录与 baseline/ 的关系（两本账，严禁混写）

| 目录 | 性质 | 再生成 |
|---|---|---|
| `../baseline/` | 机器候选（`scripts/build_f1_baseline.py` 产物） | **可随时重跑覆盖** |
| `ground_truth/`（本目录） | 人工核对定稿后的 F1 验收基准 | **任何脚本不得写入/覆盖** |

重跑 baseline 脚本只更新 `../baseline/`；本目录只允许人工编辑。若提取器升级产生新候选，走"重跑 baseline → 人工 diff 定稿 → 更新本目录"流程，不得直接覆盖。

## kind 语义与消费规则（F1 及所有下游必读）

| kind | 含义 | F1 要求清单 |
|---|---|---|
| `requirement` | 投标人须逐条响应的实质要求（★/▲标记参数、无标记措辞型模式A/B） | ✅ 取用 |

## 验收口径（本轮定稿依据）

1. **逐字符守恒**：11/11 份，全部记录 `text` 内 ★/▲ 符号总数 = 原文符号总数（零丢失零虚增）；
2. **无重复记录**：`(start, mark, text)` 联合键查重为 0（碎片级去重必须带 start，纯 text 键会把不同位置的 `业★` 误报为重复）；
3. **kind 语义核对**：芜湖 碎片5+说明语3+要求0（改判后）、滁州物业 要求14+说明语1、亳州 要求3+说明语2、南京病理 要求26+说明语1、连云港 要求56+说明语1、梁溪 说明语1；
4. **语料溯源**：见 `../语料清单.md` 公告溯源登记表（11/11 URL+发布日期闭环）。

## 已知边界（后续开发的注意事项）

- 滁州物业/芜湖的 PDF 表格断行使记录 `text` 为截短片段（如 `▲残值回`），完整条款文本需按 `start` 偏移向后吸附续行——LLM 分段抽取层处理候选段时应**取 start 前后扩展窗口**而非直接用 `text`；
- `usage_note` 正则只收录了语料实证的六类模板，新形态出现时先人工补正则再重跑，防止同类不同判。
