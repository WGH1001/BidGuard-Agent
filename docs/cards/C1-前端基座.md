# 任务卡 C1 · 前端基座（脚手架 + 三色侧栏布局 + 登录闭环 + Dashboard）

> 执行者零上下文进场：先读 `FRONTEND.md`（唯一 API 契约，全文照做），再读本卡。
> 前置：backend 10 组路由已验收入库，无需关心后端实现。

---

## 1. 任务背景

BidGuard-Agent 的 backend 已全部完成。本卡搭建前端基座：Vite + Vue3 + TS 脚手架、
三色侧栏整体布局、登录/改密/模型配置三个辅助视图、路由守卫、API/SSE 封装、Dashboard 总览页。
**后续 C2/C3 卡将在本骨架上填业务视图。**

**关于原型图与视觉差异化（本卡核心要求）**：
- `投标原型图.html` 只作视觉基调参考（低保真稿，与真实落地差距大）；
- **视觉层必须重新设计，与老项目（合同审查 Agent）明显差异化**：布局形态、卡片风格、留白节奏、
  信息密度、登录页与 Dashboard 的版式都要有自己的样子，严禁照抄蓝本外观——两个产品不能长得一样；
- 保留的视觉基线仅两项：**三色侧栏切换机制 + 默认工业浅岩灰基调**（另两色色板可重新设计）；
- 蓝本 App.vue / main.css / stores / api / router 只参考**实现机制**（主题切换怎么落 localStorage、
  菜单怎么组织、拦截器怎么写），业务页面的信息架构按 `FRONTEND.md §4` 功能清单自行设计。

## 3. 实现铁律（违反即打回）

1. **契约唯一**：一切请求路径/入参/出参以 `FRONTEND.md` 为准，严禁凭空造端点；TS 类型逐字段对齐 §2。
2. **401 处理**：axios 拦截器遇 401 清 token 跳 /login；**跨租户 404 是设计行为**，toast"不存在或无权访问"。
3. **docx 页码为 null**：所有展示页码处必须兼容 null → 显示"字符偏移 @N"（C1 的 Dashboard 不涉及，但类型定义与工具函数先备好）。
4. **SSE 用蓝本 sse.ts 的 fetch 流式方案**，事件名 progress/done/error 分发。
5. Element Plus 一律自动按需引入（unplugin-vue-components + auto-import），**禁止全量 import**；ECharts 按需注册（蓝本 DashboardView 的写法照抄）。
6. TS 严禁 `any` 滥用（确有必要时 `unknown` + 收窄）；`<script setup lang="ts">` 全覆盖。
7. 蓝本文件（附件）只读参考：**逻辑可继承，业务文案、菜单名、字段一律按 BidGuard 语义改写**（上一项目是合同审查，本项目是投标防废标——严禁出现"合同/甲方/审查报告"等旧项目残留词）。
8. 你无法运行 npm——验收在架构侧执行 `npm install && npm run build`，要求**零 TS 报错、零构建报错**；输出每个文件完整全文，严禁截断。

## 4. 验收标准

1. `npm run build` 一次性通过（架构侧执行）；
2. `npm run dev` 起本地后：登录页 → admin 登录 → 跳转 Dashboard → 侧栏 11 项可点（业务空壳页显示"建设中"占位）→ 三色切换生效 → 刷新保持登录态 → 登出回登录页；
3. Dashboard 真实消费 /api/dashboard（本地 backend 起服务后能看到 demo 任务数据）；
4. 无旧项目残留词（合同/审查/甲方/乙方/条款比对等），全局 grep 自查；
5. **视觉差异化核验**：布局形态、卡片风格、登录页版式、Dashboard 版式与蓝本截图对比明显不同（架构侧人工核验，雷同即打回重做视觉层）。
