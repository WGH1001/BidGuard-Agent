# E7 · F2 开标一览表提取鲁棒性卡（限价/报价同行防误判）

> 状态：**已立卡未派发**（2026-11-07）。启动时机：11 份仿真标书全部完成验收后。
> 背景：仿真打样两份标书在"商务承诺自洽性核验表"踩同一个坑——但这不是仿真语料特有问题，
> **真实投标书的应答表/自洽表天然就是"投标总报价 | 限价要求 | 我方报价"多列同行排版**，
> F2 必须能吃下这种形态，否则真实用户第一次上传就会被误报。

## 事故复盘（两份实锤，同一根因）

| 案例 | 表格形态 | F2 误判 |
|---|---|---|
| 滁州打样 v1 | 自洽表把"限价 580,000"和"总报价 568,000"挤同一行 | bid_total=580000，报"累加差 1.2 万"+"大写不一致"两条 error |
| 江苏一件事 v1 | `投标总报价 \| 不得高于最高限价390,000.00元 \| 382,000.00元` 三格同行 | bid_total=390000，报"累加差 8000"+"大写不匹配"两条 error |

滁州返工版把"最高限价"单独成行后 F2 归零——**语料排版合规可绕过，但提取器鲁棒性欠账仍在**。

## 根因（`core/price_extractor.py`，行级定位）

- **主根因 · 行 574-597 数字分支**：逐格扫描命中标签格"投标总报价"后，`val_part = ' '.join(uniq_cells[i+1:])` 把**同行后续所有格拼接**为值区；`_parse_money_str` 取第一个带单位金额。限价格（"不得高于最高限价390,000.00元"）排在报价格前面时被误取。
- **对照**：行 584 大写分支有 `_NON_BID_UPPER_KEYS` 排除词表，**数字分支（593-597）没有同款排除**。
- **放大器**：行 576 任何含"投标总报价"字样的表都会被标记为价格骨架（`has_price_table_skeleton`），自洽表/应答表无一幸免。

## 修复设计（四条，按优先级）

1. **限价语境数字排除（必做）**：数字分支补齐与大写分支同款的上下文排除——`clean_lbl` 或 `val_part` 含 `_NON_BID_UPPER_KEYS`（最高限价/预算金额/采购预算/拦标价等）字样时，该 val_part 不作 bid_total 候选；更精细做法：val_part 按格拆分，剔除含限价语境词的格后再解析，只保留报价语义格。
2. **同行多金额歧义护栏（必做，宁缺毋滥）**：val_part 内出现 ≥2 个**不同**金额且无法靠语境词消歧时，不赋值 bid_total（保持 None）——让"分项累加 vs 总价"校验以 NEED_MANUAL/警告形态兜底，**绝不给出错误断言**。bid_total=None 时现有下游校验行为需确认不会误报"缺失"级 error（应降级为 warning 或跳过该条勾稽）。
3. **开标一览表优先源（应做）**：若文档存在独立《开标一览表》（标题行含"开标一览/报价一览"或表头特征：项目名称+投标报价+大写并列），bid_total/bid_total_upper **只从该表赋值**；其余含"投标总报价"字样的自洽表/应答表降级为交叉核验源——只比对不赋值，交叉不一致出 warning 不出 error。
4. **大写分支同步补强（顺带）**：行 599-603 的"大写"标签分支套用同一排除与歧义护栏规则。

## 验收标准

1. **全量回归零红线**：m0_samples 11 份真实语料的 `price_cap` 命中基线（9/11）与 F2 现有单测（13+8 项）零回归；滁州返工版（合规排版）F2 保持 status OK 零告警；
2. **新用例**：构造回归用例至少覆盖——①三列同行（限价在前）；②三列同行（报价在前）；③限价语境词出现在标签格自身；④无歧义正常开标一览表（不得被误伤）；⑤双金额无语境词歧义行（应 None + warning，非错误断言）；
3. **端到端实弹**：江苏 v1 原稿（不返工排版）输入后 F2 不再报"累加不一致/大写不匹配"error——bid_total 要么正确取 382,000，要么 None+warning；江苏返工稿（排版已合规）F2 零告警；
4. 测试新增进 `tests/test_price_extractor.py` 同文件；全量 pytest 零回归方可入库。
