# E18 · 全系统双轨页码大一统卡（F1/F6/F7 三处 PDF 硬编码统一替换）

> 状态：待派发（分工由用户定）｜ 立卡：2026-11-10 ｜ 基线：commit 73e489e
> 来源：Antigravity 全仓库地毯式排查实锤——除 F4（E6）与 F2/F3（E15）外，F1/F6/F7 三模块页码仍停留在 M0 时代 `build_pdf_page_spans` 硬编码，docx 文档页码恒 None 降级裸字符偏移

## 1. 背景（三处代码实锤）

政采招标书真实语料 70% 以上是 Word docx（11 份仿真语料中 8 份 docx）。以下三处在 docx 输入时页码**全部恒 None**，前端只能显示裸字符偏移 `@N`：

1. **F1 招标红线与 ★/▲ 提取**（core/tender_extractor.py L283-290）：`build_review_checklist` 硬编码 `build_pdf_page_spans(file_path)`，docstring 自认"（docx 为 None）"。用户上传 docx 招标书提取的实质性条款/资格项/评分项 `page` 全空；
2. **F6 投前控标雷达**（core/rigging_radar.py L252/L262/L321）：`page_spans = _build_pdf_page_spans(str(tender_path))` 硬编码，docx 招标书的排他性参数页码全空（前端 RadarView.vue 已有 `formatPageOrOffset(item.page, item.offset)` 展示位，后端补上即通）；
3. **F7 标书专家追问 ReAct**（core/bid_react_agent.py L82/L370-371）：自带 `_build_pdf_page_spans`（docx 返回空列表），`search_tender`/`search_bid` 工具搜出的证据片段 docx 页码全 None，AI 引用标签只能写 `【招标文件】@字符18900` 无法给出"第 N 页"。

E15 已将统一入口公共化：`core/response_checker.py` L171-172 导出 `build_unified_page_context(file_path)`（自动分派 .pdf/.docx）与 `resolve_unified_page(offset, ctx)`（返回 (physical_or_pdf_page, footer_page, is_docx_page)）——本卡三处直接导入复用，**零新增格式分支**。

## 2. 改动清单

1. **F1（core/tender_extractor.py）**：
   - `build_review_checklist` 内：`page_spans = build_pdf_page_spans(file_path)` → `page_ctx = build_unified_page_context(file_path)`；
   - `_attach_pages` 内：`offset_to_page(it.get('start'), page_spans)` → 取 `resolve_unified_page(it.get('start'), page_ctx)[0]` 作为 page；
   - docstring 更新（删除"docx 为 None"表述）；
   - 返回结构不变（page 字段语义不变，docx 为物理页估算口径）。
2. **F6（core/rigging_radar.py）**：
   - L252 上下文构建换 `build_unified_page_context(str(tender_path))`；L262/L321 换 `resolve_unified_page(offset, ctx)[0]`；
   - 原内部别名 `_build_pdf_page_spans`/`_offset_to_page`（L27 import as）随之清理；
   - 雷达结果 dict 结构不变。
3. **F7（core/bid_react_agent.py）**：
   - L370-371：`tender_pages`/`bid_pages` → `tender_ctx = build_unified_page_context(tender_path)`、`bid_ctx = build_unified_page_context(bid_path)`（双文档各一个 ctx）；
   - 自带 `_build_pdf_page_spans`（L82）删除，改 import 公共函数；所有 `_offset_to_page(offset, pages)` 调用点换 `resolve_unified_page(offset, ctx)[0]`；
   - 工具返回与证据引用标签的 page 字段语义不变（docx 时为物理页估算）。
4. **detail_json 双轨元数据（沿用 E15 模式，仅限有 detail_json 落库的输出）**：若 F6 雷达结果落库带 detail_json，照 E15 的 `_enrich_detail_with_page_meta` 模式补 `bid_page/bid_footer_page/bid_page_is_docx`（前端 RiskCard.vue 已兼容这些 key）；F1/F7 为即时返回不落库，无需补。
