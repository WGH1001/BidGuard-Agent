## 1. 背景与老项目对照实锤

1. **多轮上下文断片原因**：[`backend/routers/qa.py`](../../backend/routers/qa.py) 虽然在数据库 `QaSession.messages_json` 保存了历史问答，但调用 [`ask_bid_expert()`](../../core/bid_react_agent.py) 时**完全未传历史对话**，导致引擎每次都从空白 `messages = [system, current_question]` 冷启动。
2. **流式思考体验差距**：老项目 `Contract-Review-Agent` 采用 `POST /api/qa/ask/stream`（`step -> answer_delta -> done`），每跑完一步工具立刻推给前端并默认展开 `<ReActSteps :default-open="true" />` 实时写明 `思考 (Thought) + 工具入参 + 返回结果`，随后流式吐字；而 BidGuard 当前只提供阻塞式同步 `POST /ask`，等待全程干转圈，且 [`ReActSteps.vue`](../../frontend/src/components/ReActSteps.vue) 默认折叠并漏配第 6 工具 `cite_regulation` 的中文名称。
3. **老项目三挡实弹避坑记录**（参考 `Contract-Review-Agent/core/react_agent.py` L167-170）：智谱 `glm-5.3-flash` 上游实测合法 `reasoning_effort` 为 `'low'` / `'high'` / `'max'`（传 `'medium'` 会触发 400-1210 拒绝而被网关降级去掉）。因此除传 `reasoning_effort` 外，还需像老项目那样按挡位联动 `max_rounds` 与 `max_tokens`（如极速=2轮 / 均衡=4轮 / 深度=6轮），确保即使某私有模型不认某一挡也能真实拉开推理深度与搜索轮数！

## 2. 改动清单（后端核心 + 路由 + 前端流式对齐，强制向后兼容）

### 2.1 `core/bid_react_agent.py`（多轮上下文注入 + 流式生成器 + 0-Token 兼容）

1. **`ask_bid_expert` 签名向后兼容扩展**（末尾新增可选参数）：
   ```python
   def ask_bid_expert(
       tender_path: str | Path,
       bid_path: str | Path,
       question: str,
       client=None,
       max_rounds: int = 6,
       reasoning_effort: Optional[str] = None,
       history: Optional[list[dict[str, Any]]] = None,
   ) -> dict[str, Any]:
   ```
   - 新增辅助函数 `_format_history_messages(history, max_turns=6, max_chars_per_msg=800)`：从 `history` 中提取 `role in ('user', 'assistant')` 的历史消息（过滤空内容或 loading 占位，按时间正序最多保留最近 `max_turns * 2` 条、单条超出 `max_chars_per_msg` 截断加 `…`），在拼接当前 `question` 之前按标准 `{'role': 'user'/'assistant', 'content': ...}` 顺序插入 `messages`；
   - **0-Token 离线降级同步支持上下文**：当 `client is None` 且当前问题较短或含指代词（如“刚才/上面/这两个/它/为什么/怎么不涉及”）而在当前句提取不到充分关键词时，从最近一条 `history` 的 `user` 消息补充检索关键词，同时答案首行可提示参考了上一轮问题主题。
2. **新增流式主入口 `ask_bid_expert_stream(...) -> Iterator[dict[str, Any]]`**：
   - 接收与 `ask_bid_expert` 完全相同的参数（包含 `reasoning_effort` 与 `history`），**不改动原 `ask_bid_expert` 的返回结构与 161 项老单测兼容**；
   - **标准产出事件帧**（参照老项目 `run_legal_qa_stream`）：
     - `{'type': 'step', 'data': {'round': int, 'thought': str, 'action': str, 'action_input': Any, 'observation': Any}}`：每完成 1 轮 ReAct（含工具调用或降级检索）**立即 `yield`**；
     - `{'type': 'answer_delta', 'data': {'text': str}}`：拿到最终 `final` 回答正文（若使用 `client.chat_stream` 则逐块流式吐出，若无或走 `chat` JSON 解析拿到 `answer` 则按自然语义分片/分段推送）实时 `yield`；
     - `{'type': 'done', 'data': {'mode': ..., 'question': ..., 'answer': str, 'quotes': [...], 'steps': [...], 'rounds_used': int, 'terminated_by_max_rounds': bool}}`：`quotes` 必须经过 `_verify_and_locate_quotes(...)` 逐字溯源锁账后才随终帧返回；
     - `{'type': 'error', 'data': {'detail': str}}`：异常兜底帧。
   - **档位联动轮次（⚠️ 挡位值必须用智谱实测合法值，与本卡避坑记录一致）**：前端三挡映射为 **⚡极速=`'low'`（封顶 3 轮）/ ⚖均衡=`'high'`（封顶 4 轮）/ 🧠深度=`'max'`（保留 6 轮）**——严禁把 `'medium'` 直接透传上游（glm-5.3-flash 实测 400-1210 拒绝，网关去参降级会让均衡挡退化成极速挡，三挡变两挡）；前端 UI 标签仍叫"均衡"，底层传 `'high'` 并靠 `max_rounds` 轮次差异与极速拉开体验；`test_e19_ux_and_concurrency.py` 若有对 `'medium'` 原样透传的断言需同步改为映射后值；`ask_bid_expert` 内部可直接消费 `ask_bid_expert_stream` 收集 `done` 帧返回（消除双份实现逻辑重复）。

### 2.2 `backend/routers/qa.py`（注入 `QaSession.messages_json` 上下文 + SSE 流式端点）

1. **提取会话历史注入点**：封装 `_extract_session_history(messages_json)`，在 **`POST /api/qa/sessions/{session_id}/ask`（同步老端点）** 和新增流式端点中，均自动将当前会话库内已存 `sess.messages_json` 作为 `history=...` 传给 `ask_bid_expert` / `ask_bid_expert_stream`——彻底消除多轮问答失忆；
2. **新增 SSE 流式端点 `POST /api/qa/sessions/{session_id}/ask/stream`**：
   - 请求体复用 `QaAskRequest`（含 `question`、`max_rounds`、`reasoning_effort`）；
   - 合法 `reasoning_effort` 校验沿用 `('low', 'medium', 'high')`（**UI 层挡位值**），路由层收到后按上表映射为上游合法值（low→low / medium→high / high→max）再透传 `client.chat`；非法值忽略为 `None`；
   - 通过 `StreamingResponse(..., media_type='text/event-stream')` 推送标准 SSE 帧（`event: step` / `event: answer_delta` / `event: done` / `event: error`，附防缓冲响应头 `Cache-Control: no-cache`, `X-Accel-Buffering: no`）；
   - 在收到 `done` 帧时把本轮 `user` 提问与 `assistant` 完整答案（含校验后的 `quotes` 和 `steps`）原子追加持久化进 `sess.messages_json`（兼容单测 SQLite 写库后更新会话标题）。

### 2.3 前端流式展示对齐老项目（`types.ts`、`api/index.ts`、`ReActSteps.vue`、`QaMessageList.vue`、`QaChatView.vue`）
