## 2. 方案 A 实现清单与 3 项必防暗坑

### 2.1 必防暗坑与工程硬约束（架构复查补充）
1. **坑 1 · 后端 SQLite 并发落库写锁竞争（`backend/routers/qa.py`）**：
   - Demo/本地默认运行在 SQLite 模式下；多条 SSE 并发跑完几乎同时触发 `write_sess.commit()` / `record_audit()` 时会撞 `sqlite3.OperationalError: database is locked`；
   - **强制解法**：在 `backend/routers/qa.py` 新增进程内串行写互斥锁（例如 `_QA_DB_WRITE_LOCK = threading.Lock()` 配合统一写库辅助函数 `_with_qa_write_lock(...)`），覆盖 `_sse_stream_gen` 的 `done` 帧写库、同步 `/ask` 写库、`DELETE .../last-turn` 撤回以及会话/附件元数据写操作，确保多流并发到达 `done` 时顺序安全落库（PostgreSQL 亦无害）。
2. **坑 2 · 同会话单流不变量（多会话并发 ≠ 同会话并发）**：
   - `Map` 化后不同 `sessionId` 允许各自并发跑 SSE；但**同一个 `sessionId` 同一时刻绝不允许存在两条活跃流**（防连点双发导致 `messages_json` 并发追加错乱或末尾回复覆盖）；
   - **强制解法**：在 `SessionRuntime` 中绑定单流令牌与 `asking` 状态——当 `runtime.asking === true` 时，当前激活会话发送按钮显式禁用并提示“当前会话正在生成中，请先停止或切换其他会话并发提问”；`send` / `regenerate` 入口强制早退校验。
3. **坑 3 · `QaChatView.vue` 组件重构粒度与 `components.d.ts` 预列**：
   - `QaChatView.vue` 当前已有 `803` 行，Map 化状态机 + 树形侧栏 + 置顶分组改动集中在本文件；需拆清纯辅助函数（如相对时间格式化、项目分组排序、Pin `localStorage` 读写），确保 `resetQaModuleCache()` 切号/登出时遍历中止并清空全部会话 runtime；
   - **会话置顶纯粹使用前端 `localStorage`**（按用户名隔离存储 `sessionId[]`），不改后端数据库 Schema；
   - 若侧栏引入 `<el-tree>` / `<el-collapse>` 等新 Element Plus 组件，遵循 `AGENTS.md` §三.7，`vite build` 可能自动更新 `frontend/src/components.d.ts`，已提前预列入本文 §4 白名单。

### 2.2 前端多会话 Runtime Map 并发（`frontend/src/views/QaChatView.vue`）
1. 建立模块级 `sessionRuntimes: Map<number, SessionRuntime>`（按 `sessionId` 隔离存储 `messages`、`asking`、`streaming`、`steps`、`attachments`、`selectedAttachmentIds`、`suggestedQuestions`、`lastTurnPersisted`、`cancelFn`），并用响应式版本号/状态集合驱动 UI 刷新；
2. 保留 `activeSessionId` 与 `selectedTaskId` 视图指针：切换会话/切换项目时仅切换当前视图指针，**不中止**其他会话仍在跑的 SSE `askStream`；后台流持续更新对应 `runtime.messages` 与 `runtime.steps`，切回该会话即可实时续看过程或最终回答；
3. 「⏹ 停止生成」按当前 `activeSessionId` 精准调用 `stopSessionStream(activeSessionId)`；`onBeforeUnmount` 保持后台流不断开（仅卸载事件监听），切换账号或登出触发 `resetQaModuleCache()` 时方全部 abort 并清空 `Map` 与全局数组；
4. `active` 状态流完成 `done` / `error` 后更新会话列表元数据，不干扰用户当前正在阅读的另一会话视图。

### 2.3 Antigravity 风格项目树形与置顶侧栏（`frontend/src/views/QaChatView.vue` & `frontend/src/api/index.ts`）
1. 启动及刷新时调用一次 `qaApi.listSessions()`（不传 `task_id` 过滤，拉取全租户全部会话）与 `checksApi.list({ task_type: 'pre_check', page: 1, page_size: 50 })`，按 `task_id` 聚合为项目树；
2. **左侧侧栏重构为两段结构**：
   - **Pinned Conversations（置顶会话区）**：展示被用户星标/图钉置顶的关键会话（会话标题 + 所属项目名称副标 + 右侧相对时间 `29m`/`1h`/`4d` + 活跃流旋转徽标 + 取消置顶）；
   - **Projects（项目树形工作区）**：每个体检任务 `BidCheckTask` 作为可折叠项目节点（`📁 项目标题`），右侧提供快捷 `+` 新建该任务下会话按钮；展开显示该项目所属会话列表（显示会话标题、相对时间；若某会话正在后台流式生成则右侧渲染动态呼吸点/加载旋转图标而非静态时间；悬停提供置顶与删除，仅当**该会话自身** `runtime.asking === true` 时禁用其删除）；
   - 当某项目下所有会话均已置顶时，保留折叠内已置顶提示（如 `N pinned conversation`）或统一复用展示，避免空项目错觉；
3. 顶部或树节点新建会话（`+`）默认仅锁按钮防重入，不再因为**另一项目或另一会话**处于 `asking=true` 而锁死整个侧栏。
