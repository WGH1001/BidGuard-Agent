## 2. 方案 A 实现清单与 3 项必防暗坑

### 2.1 必防暗坑与工程硬约束（架构复查补充）
1. **坑 1 · 后端 SQLite 并发落库写锁竞争（`backend/routers/qa.py` & `backend/models.py`）**：
   - Demo/本地默认运行在 SQLite 模式下；多条 SSE 并发跑完几乎同时触发 `write_sess.commit()` / `record_audit()` 时会撞 `sqlite3.OperationalError: database is locked` 或 WAL 读快照陈旧导致 `SQLITE_BUSY_SNAPSHOT`；
   - **已落地解法**：
     - 在 `backend/models.py` 的 `apply_sqlite_pragmas`（`_set_sqlite_pragma`）增加 `PRAGMA busy_timeout=5000`；
     - 在 `backend/routers/qa.py` 新增进程内互斥锁 `_QA_DB_WRITE_LOCK = threading.Lock()` 与统一落库函数 `_persist_qa_turn_locked(...)`（加锁前/外执行慢速 OCR 与 `ask_bid_expert(_stream)`，进入写锁后再 `rollback()` + `expire_all()` 刷新读快照后读取最新 `messages_json` 追加提交 + `record_audit`），同步覆盖 `create_qa_session`、`upload_qa_attachment`（持锁复检附件数量与容量配额）、`delete_qa_attachment`、`delete_qa_session`、`ask_in_session`、`ask_in_session_stream`（入流前 `db.rollback()`、`done` 帧走短生命周期 `write_session_factory`）与 `withdraw_last_turn_in_session`。
2. **坑 2 · 同会话单流不变量（多会话并发 ≠ 同会话并发）**：
   - `Map` 化后不同 `sessionId` 允许各自并发跑 SSE；但**同一个 `sessionId` 同一时刻绝不允许存在两条活跃流**（防连点双发导致 `messages_json` 并发追加错乱或末尾回复覆盖）；
   - **已落地解法**：在 `QaSessionRuntime` 中绑定 `streamToken` 与 `asking` 状态——当 `rt.asking === true` 时，当前激活会话禁用发送/重试并提示切换其他会话并发提问；发送入口早退校验并校验流回执时的 `streamToken`。
3. **坑 3 · `QaChatView.vue` 组件重构粒度与 `components.d.ts` 预列**：
   - 复用现有布局与按钮原语未引入新 Element Plus 组件，`vite build` 后核对 `frontend/src/components.d.ts` 零变更；
   - 将会话置顶持久化（`PINNED_STORAGE_PREFIX = 'bidguard_qa_pinned_sessions_v1_'`，按登录用户名隔离）、UTC 补 `'Z'` 相对时间格式化（`29m` / `1h` / `4d`）、项目树按 `task_id` 聚合与 `resetQaModuleCache()`（`stopAllQaStreams()` 中止全部分支流）拆分清楚。

### 2.2 前端多会话 Runtime Map 并发（`frontend/src/views/QaChatView.vue`）
1. 建立模块级并发状态映射 `cachedRuntimes = ref<Record<number, QaSessionRuntime>>({})`（按 `sessionId` 隔离 `messages`、`asking`、`cancelFn`、`streamToken`、`attachments`、`selectedAttachmentIds`、`suggestedQuestions`、`lastTurnPersisted`、`hydrated`、`uploadingAttachment`）；
2. 保留 `cachedActiveSessionId` 与 `cachedSelectedTaskId` 视图指针：切换会话/切换项目仅切换当前视图，**不中止**其他会话仍在跑的 SSE `askStream`；后台流持续更新对应 `QaSessionRuntime`，且 `selectSession` 对正在 `asking` 的活跃流免于被旧快照覆盖；
3. 「⏹ 停止生成」经 `stopSessionStream(activeSessionId)` 精准中止当前活跃会话；登出或切号触发 `resetQaModuleCache()` 时调用 `stopAllQaStreams()` 中止全部流并清空全部运行态。

### 2.3 Antigravity 风格项目树形与置顶侧栏（`frontend/src/views/QaChatView.vue` & `frontend/src/api/index.ts`）
1. 启动及刷新时调用一次 `qaApi.listSessions()`（不传 `task_id` 过滤，拉取全租户全部会话）与 `checksApi.list({ task_type: 'pre_check', page: 1, page_size: 50 })`，按 `task_id` 聚合为项目树；
2. **左侧侧栏重构为两段结构**：
   - **Pinned Conversations（置顶会话区）**：展示被用户星标/图钉置顶的关键会话（会话标题 + 所属项目名称副标 + 右侧相对时间 `29m`/`1h`/`4d` + 活跃流旋转徽标 + 取消置顶）；
   - **Projects（项目树形工作区）**：每个体检任务 `BidCheckTask` 作为可折叠项目节点（`📁 项目标题`），右侧提供快捷 `+` 新建该任务下会话按钮；展开显示该项目所属会话列表（显示会话标题、相对时间；若某会话正在后台流式生成则右侧渲染动态呼吸点/加载旋转图标而非静态时间；悬停提供置顶与删除，仅当**该会话自身** `runtime.asking === true` 时禁用其删除）；
   - 当某项目下所有会话均已置顶时，保留折叠内已置顶提示（如 `N pinned conversation`）或统一复用展示，避免空项目错觉；
3. 顶部或树节点新建会话（`+`）默认仅锁按钮防重入，不再因为**另一项目或另一会话**处于 `asking=true` 而锁死整个侧栏。

### 2.4 验收补强：F7 会话重命名 / 首问自动命名与 F1 概览条网格对齐（2026-11-16 追加）
