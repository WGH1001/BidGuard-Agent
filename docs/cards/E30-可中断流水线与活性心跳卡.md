# E30 · 可中断流水线与活性心跳卡（任务取消 / F1 内部进度 / 启动恢复 stale 任务 / 雷达与提取取消）

> 来源：2026-11-16 实战排障——任务 #40（江苏固废，自定义 LLM 配置 + Docker）F1 提取中停留 15 分钟，暴露三重缺口，最终只能重启容器 + 手工 SQL 置终态清理。
> 裁决补充（架构侧复核批复）：

> 2. **F6 控标雷达接入同一套服务端 `_cancel_flags`**：Radar 任务本身即为 `bid_check_tasks` 行，不能只靠前端 `AbortController`；服务端 `_execute_radar_scan` 注册并检查 `_cancel_flags`，取消/异常一律落 `failed` 消灭僵尸 `checking` 记录；`ExtractView.vue`（无 DB 行）采用前端 `AbortController` 中止并清空排队队列。
> 分工：Antigravity 实现，架构侧卡复核 + 独立机检验收。

## 1. 实测定位的缺口清单

1. **执行线程完全失控**：`BidTaskWorker.submit_check_task`（`backend/worker.py` L480）将任务提交线程池后无任何取消手段——全文无 cancel flag / stop_event；
2. **运行中任务拒删 409**：`DELETE /api/checks/{task_id}`（`backend/routers/checks.py` L596-602）对运行中任务一律拒绝——卡住的任务在 UI 上无法移除，"彻底死掉"；
3. **启动无 stale 恢复**：backend 启动时不会把遗留的非终态 `running` 任务复位，重启后任务永远显示"运行中"（本次已手工执行 `UPDATE bid_check_tasks SET status='failed' WHERE id=40 ...` 清理）；
4. **F1 内部进度不可见**：F1 大模型逐条款串行判定为分钟级（大标书 15+ 分钟属正常），但进度帧只在阶段边界发——用户无法区分"慢"与"死"；
5. **F6 控标雷达僵尸 `checking` 与 F1 独立提取队列无中止**：`POST /api/radar` 先提交 `status='checking'` 再跑同步 LLM 循环，异常/重启即成永久 `409` 删不掉的僵尸记录；`ExtractView.vue` 多文件提取锁定后无取消入口。

## 2. 改动清单（4 块 + 补强）

### 2.1 协作式取消（核心）
1. **`backend/worker.py` + `core/` 三处循环透传**：
   - 定义 `class _PipelineCancelled(BaseException): pass`（别名 `PipelineCancelled` 供 `radar.py` 复用）；`BidTaskWorker` 新增 `_cancel_flags: dict[int, threading.Event]` 与 `register_task_execution` / `unregister_task_execution` / `request_cancel` / `is_cancel_requested` / `check_cancelled`；
   - **取消检查点**（命中即抛 `_PipelineCancelled(BaseException)`，由 `_run_pipeline` / `_execute_radar_scan` 顶层捕获统一收尾）：
     - 每个阶段边界（F1 前 / Stage 1.5 前 / F2 前 / F3 前 / F4 前 / grading 前）必查；
     - **F1 逐条款 LLM 循环内每次迭代**（`core/tender_llm.py` `extract_tender_with_llm(..., progress_cb=...)`，且 `worker.py` L591 `except Exception:` 前显式保留 `_PipelineCancelled` 上抛不被降级吞掉）；
     - Stage 1.5 OCR 逐图循环：经现有 `progress_cb` 链路透传（因继承 `BaseException`，直接穿透 `core/parser.py` 的 `except Exception:` 中断循环）；
     - F4 逐条款并发批次归位间（`core/response_checker.py` `run_response_check(..., progress_cb=...)`，中断时立即 `pool.shutdown(wait=False, cancel_futures=True)`）；
     - F6 控标雷达循环内同款接入（`core/rigging_radar.py` `scan_rigging_radar(..., progress_cb=...)` + `backend/routers/radar.py` 注册并检查 `_cancel_flags`，异常或取消均落 `failed`）。
   - **取消终态不新增状态枚举**：`status='failed'` + `stage_detail='用户中断'` + `error_msg='用户中断'` + `config_json['cancelled_by_user']=True`（对齐五态机，前端改动最小）；收尾时清 `_in_flight` / `_cancel_flags`、清理 `BidFinding` 与半成品产物（复用 `_cleanup_task_deviation_artifacts`）、SSE 发 `error` 终止帧（附带 `updated_at`）。
2. **`backend/routers/checks.py`**：
   - 新增 `POST /api/checks/{task_id}/cancel`：租户隔离 404、非运行中返回 409（`TASK_NOT_RUNNING`）、触发 `worker.request_cancel` 并立即更新 DB 终态与审计留痕 `cancel_check_task`；
   - `DELETE /{task_id}` 对运行中任务保持 409，但 message 改为 `"运行中任务请先中断后再删除"`。
3. **重跑清理与徽标修正**：`_reset_task_for_rerun` 清理旧 `_cancel_flags` 并置空旧 `task.stats_json = None`（修复重跑中顶栏误显示上轮 `0-Token` 徽标 Bug）；`sync=True` 同走 `_run_pipeline` 统一取消收尾。

### 2.2 F1 内部心跳进度 + 前端判活（一石二鸟）
1. **`backend/worker.py`**：`_emit_stage` 与初始 SSE 帧均携带 `updated_at`；F1 逐条款循环内每 ≥5s（及末条）发一次轻量 progress 帧（progress 仍 20%，`stage_detail='F1 正在逐条判定废标红线与实质性条款（已判定 X / Y 条）'`）；
2. **前端判活**：`CheckDetailView.vue` `handleSseProgress` 同步更新 `currentTask` 与左侧 `tasks` 数组对应任务的 `updated_at`；`CheckTaskList.vue` 显示 `"最近活动 Xs 前"`；**超过 120s 无任何帧**时卡片显示 `"疑似无响应，可中断"` 提示——以后 `"慢"` 与 `"死"` 一眼可分。

### 2.3 启动恢复 stale 任务
- **`backend/main.py`**：新增 `recover_stale_tasks()` 并接入 `lifespan` 启动钩子：将 `status IN ('extracting','checking','grading')` 的遗留任务（含 `pre_check` 与 `radar`）统一置为 `status='failed'`、`stage_detail='服务重启中断'`、`error_msg='服务重启中断'`，清空 broadcaster 缓存并审计留痕 `recover_stale_tasks`。

### 2.4 前端中断入口（检查台账/详情 + F6 雷达 + F1 独立提取）
- **`frontend/src/api/types.ts` + `index.ts` + `http.ts`**：`SSEProgressFrame` 补 `updated_at`；新增 `checksApi.cancel(taskId)`；`extractApi.extract` / `radarApi.scan` / `radarApi.rescan` 支持可选 `signal?: AbortSignal`（主动 Abort 抑制误导错误弹窗）；
- **`frontend/src/components/CheckTaskList.vue` + `frontend/src/views/CheckDetailView.vue` + `frontend/src/components/SseProgress.vue`**：左侧任务卡与右侧详情顶部操作舱在运行中均提供「中断」按钮（`ElMessageBox` 确认弹窗，文案说明 `"中断后本任务标记为失败，可删除或重新发起体检"`）与 120s 无响应提示；运行中隐藏旧 `stats_json` 的 `0-Token` 徽标；
- **`frontend/src/views/RadarView.vue` + `frontend/src/views/ExtractView.vue`**：`RadarView.vue` 提供「⏹ 停止扫描」按钮（清排队队列 + 调服务端 `checksApi.cancel` 置位 `_cancel_flags` + 中止请求，并对历史列表中卡在 `checking` 的项提供「中断」按钮）；`ExtractView.vue` 提供「⏹ 取消提取」按钮（清排队队列 + `AbortController` 立即解锁界面）。
