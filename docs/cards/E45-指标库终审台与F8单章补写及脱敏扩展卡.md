## 1. 核心目标

1. **企业常见指标库与多业务线评分标准：在线管理 + 扩展新业务线 + 人工终审转正**：
   - E41 已交付 `common`/`security`/`maas` 三份指标库，但目前 `review_status` 全为 `pending_human_review`，且仅能手工修改磁盘 JSON；
   - 新增前后端闭环管理台（挂载于 `RulesAndCertsView.vue` 第四页签「企业指标与业务线评分库」），支持业务/管理员在线查看与填充 `[待人工确认：...]` 硬指标槽位、增删改常见指标及典型评分标准提示、新增自定义业务线（如 `cloud`/`gov_data`），并支持管理员一键签署**「人工终审通过（`approved`）」**写回留痕；
   - **沿用 AGENTS.md 铁律 9 防造假硬锁**：写入时强制跑 `sanitize_indicator_text` / `_BID_MONEY_RE` 拦截具体人民币投标报价数字，所有写盘均原子覆盖 `data/rules/indicator_library/` 并严禁触碰 `ground_truth/`。
2. **F8 标书编制「单章节专项补写 + 多附件协同 + 篇幅/表格快捷预设」（E42 → F8 闭环 & WPS 高价值对齐）**：
   - 支持用户从 E42《提分诊断》「重点提分行动抓手」一键携带薄弱评分点（如 `培训方案`/`售后服务方案`/`项目进度计划`）跳入 `/composer`，切换为 **「单章节专项补写（`compose_scope='section'`）」**：无需重跑整本封面/资质/开标函，直接针对该评分要求 + 失分短板 + 多份企业参考资料（工程量清单/可研报告/历史方案 `.docx`/`.pdf`/`.txt`）+ 所选业务线指标库，生成高分点对点专项章节 `.docx`；
   - 在 `BidComposerView.vue` 顶部提供类似 WPS 的「生成范围切换（完整标书 / 单章节专项）」「篇幅与表格密度预设（简明 / 标准 / 详尽｜丰富表格 / 适中 / 无表格）」及「招标评分要点原文对照折叠栏」。
3. **隐私合规脱敏引擎口径可控扩展（基础 2 增强）**：
   - 保留现有 `18 位身份证 + 语境银行卡/对公账号` 默认零回归；
   - 在 `core/privacy_sanitizer.py` 新增环境变量控制的可选开关 `PRIVACY_MASK_CONTACT_ENABLED`（默认 `'0'` 或按部署环境开启 `'1'`），开启后自动对 **11 位中国大陆手机号（排除项目/合同/标准/金额序列及传真固话前缀误伤）与电子邮箱地址** 执行等长幂等掩码（手机号保留前 3 后 4；邮箱保留首字母与域名后缀），并在 `PrivacyStatsOut` 回显 `phone_masked` / `email_masked`。

## 2. 技术设计明细

### §2.1 `core/indicator_library.py` & `backend/routers/composer.py`（指标库持久化维护与人工终审）

1. **核心库读写与自定义业务线注册表（`core/indicator_library.py`）**：
   - 新增业务线元信息扫描 `list_indicator_lines(library_dir=None)`：除 `common`/`security`/`maas` 内置三线外，自动发现同目录下合法 `{line_key}_indicators.json`（限制 `^[a-z][a-z0-9_]{1,23}$` 防路径穿越）；
   - 新增 CRUD 与终审函数（全部使用 `encoding='utf-8'`, `newline='\n'` + 临时文件 `os.replace` 原子写盘）：
     - `create_indicator_line(line_key, display_name, description, line_scoring_summary, *, library_dir=None)`；
     - `upsert_indicator_entry(line_key, entry_payload, *, library_dir=None)`：写入前强制运行 `_BID_MONEY_RE` 检验与 `sanitize_indicator_text`，若提交正文中混入未占位具体人民币投标总价/折扣（非允许的合规限期/数量词）可选拒绝并返回结构化错误或强制槽位化，保存后重算 `content_hash`；若该线原已 `approved` 且发生实质条目修改，自动重置为 `pending_human_review` 提醒复审；
     - `delete_indicator_entry(line_key, indicator_id, *, library_dir=None)`；
     - `approve_indicator_line(line_key, reviewed_by, *, library_dir=None)`：校验所有条目已无非法裸报价且通过完整性检查后置 `review_status='approved'`、`reviewed_by`、`reviewed_at`（UTC ISO）。
2. **REST 管理端点（`backend/routers/composer.py`，零新增数据库表，保持 14 表不变）**：
   - `GET /api/composer/indicators/lines`：列出全部可用业务线概览与审核状态；
   - `POST /api/composer/indicators/lines`（`require_admin`）：新增业务线与典型评分维度权重参考；
   - `POST /api/composer/indicators/entries` / `PUT /api/composer/indicators/entries/{indicator_id}` / `DELETE /api/composer/indicators/entries/{indicator_id}`（`require_admin`，记 `AuditLog` 留痕，操作后使相关检索概览立即可见）；
   - `POST /api/composer/indicators/approve`（`require_admin`）：将指定业务线标为已人工终审通过并写 `AuditLog(action='approve_indicator_library')`。

### §2.2 `core/bid_composer.py` & `/api/composer/generate`（F8 单章节专项补写 + 多附件协同 + 密度档位）

1. **`core/bid_composer.py`**：
   - `compose_bid_blueprint` 新增向后兼容 keyword-only 参数：
     - `compose_scope: Literal['full', 'section'] = 'full'`
     - `target_section_topic: Optional[str] = None`
     - `target_section_guidance: Optional[str] = None`（例如承接 E42 诊断报告中的 `deduction_reasons` / `improvement_suggestions`）
     - `density_preset: Literal['concise', 'standard', 'detailed'] = 'standard'`
     - `table_density: Literal['rich', 'moderate', 'none'] = 'rich'`
   - 当 `compose_scope == 'section'` 时：
     - 跳过完整封面大页/全套资质独立附页/开标报价表生成，仅构造「1. 专项补写目标与招标评分依据锚定」+「2. 目标章节高分应答方案（支持多份 `knowledge_files` + 所选业务线 `IndicatorLibraryProvider` 协同注入 + 暗标双模式复用 `blind_bid_mode`）」；
     - 导出独立轻量 `.docx`（`{task_title}_专项补写_{topic}.docx`），方便用户直接复制到原标书对应章节，不破坏原书编号体系；
   - 同时保留 `blueprint_json` 中 `tender_scoring_focus` 摘要供前端「招标评分要点对照面板」直接阅读。
2. **`backend/routers/composer.py` + `schemas.py`**：
   - `POST /api/composer/generate` 扩展可选 Form 字段 `compose_scope`（默认 `'full'`）、`target_section_topic`、`target_section_guidance`、`density_preset`、`table_density`（继续复用 E38 异步队列、E41 指标库、E43 暗标防废标模式，多 `knowledge_files` 全部喂入 `LocalKnowledgeSnippetProvider` 并清理持久化中的宿主路径）；
   - `ComposeDraftSummaryOut` 增透 `compose_scope` 与 `target_section_topic`。

### §2.3 `core/privacy_sanitizer.py` & `PrivacyStatsOut`（手机号/邮箱可控屏蔽扩展）

1. **`core/privacy_sanitizer.py`**：
   - 新增开关函数 `is_contact_privacy_mask_enabled() -> bool`（读取 `PRIVACY_MASK_CONTACT_ENABLED`，默认 `'0'` 保持现有口径稳定；传参 `mask_contacts: Optional[bool] = None` 供单测与显式调用测试）；
   - 新增精准 11 位大陆手机号与电子邮箱正则屏蔽（保留前 3 后 4 / 邮箱保留首字符与域名，严格排除 `项目编号`/`标准号`/`传真`/`400热线` 与连续长数字子串，严格等长与幂等）；
   - `sanitize_text` 返回计数扩展兼容 `phone_masked` / `email_masked` 字段（`scan_document_file` 依旧严守 `ocr_images=False` 铁律 8）。
2. **`backend/schemas.py` & `core/llm_gateway.py`**：
   - `PrivacyStatsOut` 新增可选 `phone_masked: int = 0`、`email_masked: int = 0`（全向后兼容既有 `{id_masked, bank_masked}`）；`LLMClient.total_usage()` 同步统计 `privacy_phone_masked` / `privacy_email_masked`。

   - `CheckDetailView.vue` E42「Top-5 提分抓手」跳转 `/composer` 时自动带参 `compose_scope=section&topic=...&guidance=...&taskId=...`；
