# E42 · 标书评分预估与提分建议卡（紧随 E43 串行落地）

> 状态：**已完成全量实现与实测验收（工作区待确认 commit）** ｜ 代码基线：**E43 `093013d`（330 项 pytest 全绿 + `vite build` 1865 模块零错误，`components.d.ts` 零改动）** ｜ 共享文件串行范围：`types.ts`/`index.ts`/`schemas.py`（无需修改 `worker.py`）
> 领导需求映射：**业务 2「标书评分预估（根据标书正文质量进行评估）」**，并将 F1/F2/F3/F4/E43 检出的合规与废标信号串联成可核查的得分诊断闭环。

---

## 1. 核心目标

1. **逐项评分细则 vs 投标正文质量预估（拒绝黑盒拍脑袋打分）**：新建 `core/bid_scorer.py`，按招标文件提取的《评分细则》（同时兼容 `.docx` 评分表与 `.pdf` 段落/表格评分项）逐条评估我方投标文件正文质量，输出**分项满分、预估得分、得分置信状态、具体失分原因、可操作提分建议及原文依据溯源**。
2. **废标/一票否决先导联动（消费 E43 + F2/F3/F4 实锤发现）**：
   - 若 F3（证照过期/串名）、F2（超最高限价/严重算术错）或 **E43（`BLIND_BID_IDENTITY_LEAK` / `BLIND_BID_STYLE_VIOLATION`）** 触发 `consequence='veto'`，在评估总览强制亮出**「存在疑似一票否决项（优先清零废标风险）」**红线提示，避免用户被单纯正文高分误导；
   - 价格分项诚实处理：因评标基准价取决于竞争对手开标报价，系统**严禁捏造竞争对手均值或精确价格得分**，明确标为 `pending_open_bid`（附报价规范性与不超限价核验结果及权重上限）。
3. **防幻觉与确定性守恒锁（铁律 1/2/3/4）**：
   - 分值合计、满分汇总与百分比计算 100% 使用 `Decimal`（`ROUND_HALF_UP` 量化至 `0.1` 或 `0.01`），单条 `0 <= estimated_score <= max_score` 由 Python 强制钳位；
   - 客观扣分规则（如“每 1 项技术需求不满足扣 2 分”）结合 F4 核验结果与确定性规则校验上限；
   - 所有投标正文摘录强制过 `quote_verifier.verify_quote()` 核验，未过核验一律清空并标 `quote_verified=False`；
   - `client=None`（0-Token 离线降级模式）时正常运行确定性维度 + 本地混合检索证据覆盖率预筛，并将主观质量项诚实标为 `status='need_llm'`（`status_reason='no_llm_client'`，绝不报错阻断或编造分数）。

## 2. 技术设计明细

### §2.1 新模块 `core/bid_scorer.py`（评分细则统一抽取 + 局部窗评估 + 诊断报告导出）
1. **`collect_scoring_criteria_items(tender_path, *, f1_res=None, client=None) -> dict[str, Any]`**：
   - 统一整合 F1 已提取的 `scoring_tables`（`.docx` 100 分校准表）、`scoring_prose` 与 PDF 评分文本片段——将 `bid_composer._extract_pdf_scoring_items` 重构扩展 `include_price: bool = False`（F8 保持默认 `False` 零改动，`bid_scorer` 显式传 `include_price=True`，**防漏抓 PDF 价格分导致 `items_sum` 失衡误报**），归纳出标准 `CriterionItem` 列表：`{criterion_id, category: 'price'|'business'|'technical'|'service'|'qualification', section, factor, max_score: Decimal, scoring_rule_text, evaluation_mode: 'price_formula'|'objective_deduction'|'subjective_quality'}`；
   - 计算并核对 `declared_total_max` 与 `items_sum`（不等 `100` 时诚实标注 `score_scale_warning`，不强行篡改原文分值）。
2. **`estimate_bid_score(...) -> dict[str, Any]`**：
   - 入参：`tender_path, bid_path, *, f1_res=None, f2_res=None, f3_findings=None, f4_findings=None, blind_bid_findings=None, client=None, tender_parsed_doc=None, bid_parsed_doc=None, progress_cb=None, cancel_check=None`；
   - **三类评分项分层评估**：
     - **`price_formula`（价格分）**：仅结合 F2 `run_price_check` 结果检查是否超限价/算术一致，得分置 `None`，说明“评标基准价依赖开标现场各投标人报价，此处确认报价合法性与价格分占比”；
     - **`objective_deduction`（客观/业绩/证照/响应扣分项）**：优先对照 F3 `cert_ledger_summary`/F4 `★▲` 检出与本地正文检索统计进行确定性/半确定性初评；若规则含“每不满足 1 项扣 N 分”，用 `Decimal` 扣减（下限 `0`）；无法正则拆解的规则诚实标为 `status='need_llm'`（`status_reason='ambiguous_deduction_rule'`）；
     - **`subjective_quality`（主观方案与服务评分项）**：通过 `core/hybrid_retriever.hybrid_retrieve_windows` 从投标书取 Top-3 局部证据窗口（严禁整本直塞），结合对应招标评分细则与（可选）F4 异常摘要送 `client.chat`（使用网关当前低温配置 `temperature=0.2`，**不修改 `core/llm_gateway.py`**）评估质量、覆盖缺口、失分点与提分建议；每条输出强制经 Python `Decimal` 钳位（`[0, max_score]`）及 `verify_quote` 核验摘录，支持 `ThreadPoolExecutor` 受控并发与 `cancel_check`（穿透 `BaseException`）；单条调用异常/无模型降级标 `status='need_llm'`（`status_reason='llm_call_failed'|'no_llm_client'`）不阻断全局；
   - **汇总产出**：
     - `veto_alerts`（汇总 F2/F3/F4/E43 触发 `consequence='veto'` 的阻断风险）；
     - `assessed_max_score` / `assessed_estimated_score` / `price_pending_max_score` / `total_declared_max_score`（全程 `Decimal` 序列化为字符串或 2 位小数）；
     - `items`: 逐条明细（含 `criterion_id`, `factor`, `category`, `max_score`, `estimated_score`, **统一四态** `status: 'evaluated'|'pending_open_bid'|'veto_risk'|'need_llm'`, `status_reason`, `score_ratio_pct`, `deduction_reasons`, `improvement_suggestions`, `evidence_quotes`）；
     - `top_priorities`: 按可挽回分值空间从高到低排序的 Top-5 提分抓手（可附带建议前往 F8 补写章节提示）。
3. **`export_score_estimate_docx(estimate_result, output_path) -> Path`**：
   - 导出《标书预估得分与提分诊断报告.docx》（含总览结论与一票否决警示表、分项预估得分与扣分/提分建议明细表、重点提分行动清单）；
   - **报告封面与页眉强标注「AI 质量自评预估（非最终评委实际打分）」免责声明**（三条防幻觉红线之一，与前端 UI 同款措辞，不得省略）。

### §2.2 持久化、异步调度与 API（`backend/models.py` + `backend/routers/checks.py` + `backend/schemas.py`，零改动 `worker.py`/`main.py`）
1. **持久化扩展与状态信封（零拆表回归）**：
   - 在 `BidCheckTask`（第 3 表）新增 `score_estimate_json = Column(JSON, nullable=True)` 及老库平滑加列守卫 `ensure_bid_check_tasks_e42_columns`（同步挂载至 `after_create` 与 `apply_sqlite_pragmas`，表总数保持 14 表不变）；并顺手更新 `BidFinding.source_module` 行注释补入 `'BLIND_BID'`（履行 E43 顺延约定）；
   - `score_estimate_json` 顶层自带轻量状态信封（`status: 'queued'|'running'|'completed'|'failed'`, `progress: int`, `stage_detail: str`, `error_msg: Optional[str]`），无需新增数据库列或改动 `backend/main.py`。
2. **后台调度、防重与中断复用**：
   - 复用现有 `BidTaskWorker.submit_background_job(f"score:{task_id}", ...)`（`sync=False` 支持后台异步跑、`sync=True` 供单测同步验证）及 `f"score:{task_id}" in worker._in_flight` 运行态判重，透传 `worker.check_cancelled(f"score:{task_id}", cancel_ev)` 与 `PipelineCancelled`。
3. **新增 REST 端点（挂载于 `/api/checks/{task_id}/score-estimate`）**：
   - `POST /api/checks/{task_id}/score-estimate`（可选 `async_run: bool = Query(default=False)`）：读取已上传的 `tender_path` / `bid_path` 与该任务已有 `BidFinding`（自动纳入 F2/F3/F4 与 **E43 暗标 `BLIND_BID_*` 发现**），运行 `estimate_bid_score` 并持久化 `task.score_estimate_json`；若主任务处于 `extracting/checking/grading` 返回 `409 CHECK_TASK_RUNNING`，若 `f"score:{task_id}" in worker._in_flight` 正在评估则返回 `409 SCORE_ESTIMATE_RUNNING`；
   - `GET /api/checks/{task_id}/score-estimate`：读取已保存的评分预估快照；若检测到库内 `status in ('queued','running')` 但 `f"score:{task_id}" not in worker._in_flight`（进程重启遗留态），自动懒收敛置 `'failed'`（`error_msg='服务重启中断评分预估，请重新发起'`）并回写，防前端永久轮询死锁；
   - `GET /api/checks/{task_id}/score-estimate/export`：校验存在 `status == 'completed'` 快照（否则返回 `404 SCORE_ESTIMATE_NOT_FOUND`）后生成并下载《标书预估得分与提分诊断报告.docx》（记审计日志 `export_score_estimate`）。

## 3. 验收标准

1. **单测覆盖**：
   - `Decimal` 评分钳位（越界分数防溢出、汇总精度 0.01/0.1 一致性）、价格分诚实置 `None`（绝不虚构竞争对手报价基准）；
   - 一票否决联动（注入 F3 证照过期或 **E43 暗标违规发现（`source_module='BLIND_BID'`，code `BLIND_BID_*`）** 时，`veto_alerts` 准确捕获并亮红）；
   - LLM 主观评估与 `verify_quote` 溯源拦截（虚假摘录清空置 `quote_verified=False`）、`client=None` 0-Token 降级模式全流程不报错；
   - API 全流程（`POST`/`GET`/`export`、多租户 404 隔离、`409 CHECK_TASK_RUNNING`、老库 `score_estimate_json` 平滑加列）与实弹探针（基于真招标 PDF 评分细则 + 投标书正文跑出合理分项预估与提分建议并导出有效 `.docx`）。
2. **已知质量制约与稳定化要求（实现必读）**：
   - **F1 评分细则精度制约**：段落型评分细则提取存在已知粒度方差（HANDOVER §5.1 Backlog：梁溪/亳州/滁州物业存在跨窗超计与波动）——评分预估质量直接受其制约，卡内 `score_scale_warning`（分值合计≠100 诚实告警）必须落位且 UI 可见，**严禁静默吞掉错分值**；
   - **主观项评分稳定性**：`subjective_quality` 项的 LLM 调用复用网关当前最低温设定（`core/llm_gateway.py` 默认 `temperature=0.2`，不修改核心网关三出口），同一标书重复评估的分项分波动应可解释；单条评分失败/超时按既有单条降级处理（统一置 `status='need_llm'`，并通过 `status_reason` 标注 `'llm_call_failed'` 或 `'no_llm_client'`），严禁半途报错阻断整份报告；
   - **客观扣分规则解析边界**："每不满足 1 项扣 N 分"类规则文本千变万化，正则解析不出的诚实标 `status='need_llm'`（`status_reason='ambiguous_deduction_rule'`），严禁硬猜扣分数字。
3. **实弹探针语料（点名弹药）**：使用 `data/corpus/sim_bids/` 已验收的 11 份仿真投标书与 `m0_samples` 真招标书（**只读访问，严禁写入 `data/corpus/m0_samples/ground_truth/`**）配对跑通全流程（评分细则提取 → 分项预估 → `veto_alerts` → `.docx` 导出），重点选含段落型评分细则与表格型评分细则各至少 1 份（单测默认走 0-Token + Mock 离线断言，不依赖外网 Key）。
4. **全量回归**：全量 `pytest`（330 项基线 + E42 新增）零回归 + `vue-tsc --noEmit && vite build` 零错误且 `components.d.ts` 无变动。
