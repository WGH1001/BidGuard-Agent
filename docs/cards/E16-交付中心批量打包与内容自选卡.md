# E16 · 交付中心批量打包与内容自选卡

> 状态：已派发 Gemini（2026-11-09）｜ 立卡：2026-11-09 ｜ 基线：commit 6af95dc
> 来源：用户实测反馈"封标交付中心应支持批量打包与自主选择打包内容"（采纳部分建议：行内 ZIP 快捷按钮保留）

## 1. 背景与现状

交付中心现状（`backend/routers/reports.py`）：单任务一键 ZIP（标红原件 + 偏离表.docx + 人工终核签字单.docx），固定三件套、不可选内容、不支持批量。前端 `ReportsAndAuditView.vue` 每行四个按钮（投标书原件 / 标红批注件 / 交付包 ZIP / 删除）。

用户裁定：**新增批量打包与打包内容自选；行内"交付包 ZIP"快捷按钮保留不动**（单任务一键下载是高频动作）。

## 2. 改动清单

1. **后端（backend/routers/reports.py）**：
   - 将 `export_task_deliver_zip` 的打包核心提炼为辅助函数 `_build_task_deliver_zip(task_id, include: set[str]) -> Path`，include 取值 `{'original','redline','deviation','signoff'}`（original=投标书原件，redline=标红批注件，deviation=偏离表.docx，signoff=终核签字单.docx）；
   - 新增 `POST /api/reports/batch-zip`：请求体 `{task_ids: [...], include: [...]}`；逐任务调用辅助函数生成子 ZIP，全部装入一个批次大包 `output/deliver/batch_{utc_ts}_交付包.zip`（大包内每个任务一个子目录，命名 `{task_id}_{任务标题}/`）；
   - **诚实降级**：某任务源文件缺失/未完成时跳过该任务并在响应 JSON 的 `failed: [{task_id, reason}]` 中列出，绝不静默吞错；全部失败返回 422；
   - 权限与审计与既有单任务端点保持一致（record_audit，action='export_batch_zip'）；
   - 既有单任务端点行为一字不动。
2. **前端（frontend/src/views/ReportsAndAuditView.vue + api/types.ts）**：
   - 交付台账列表每行加复选框；表格上方新增"批量打包"按钮（选中 ≥1 时可用）；
   - 点击弹出打包配置弹窗：四个内容复选框（投标书原件 / 标红批注件 / 偏离表.docx / 终核签字单.docx，默认全选）+ 已选任务数提示；
   - 调用 batch-zip 下载大 ZIP；响应含 failed 清单时 toast 明示哪些任务被跳过及原因；
   - types.ts 补齐批量端点请求/响应类型。

## 3. 验收标准

1. pytest 新增（tests/test_reports_batch.py 或并入既有）：① 两个正常任务 + include 全选 → 大 ZIP 内含两个子目录且各含所选文件；② include 仅 {'original'} → 子包只含原件；③ 一个任务源文件缺失 → 跳过且响应 failed 列出原因，其余正常；④ 审计日志含 export_batch_zip；
2. 全量 pytest（基线 151 项 + 新增）零回归全绿；vue-tsc --noEmit 零错误；
3. 前端走查：复选框、批量按钮禁用态、弹窗、failed toast 均正常。

## 4. 铁律

- commit 信息用中文；批量打包失败严禁静默吞（诚实列出）；行内单任务 ZIP 按钮行为不得改动；落盘路径与命名风格沿用 output/deliver/ 既有约定。
