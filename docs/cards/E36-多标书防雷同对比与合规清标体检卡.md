## 1. 业务背景与技术难点

实际项目参选至少需 3 家单位递交投标文件；若多份标书出现高比例雷同、同一非招标错别字或同一编标电脑元数据，清标系统或评标委员会将直接按“异常一致 / 同一单位或个人编制”视为串通投标予以废标并触发法律风险。

技术上最致命的误报坑点在于：**三家标书都必须原样抄写《招标文件》中的条款原文、偏离表左侧要求与法定制式格式标题**——若直接对两份投标书做全文查重，未剔除招标底稿与公文套话的相似度会虚高到 50%~70%，彻底失去排查价值。

## 3. 核心设计方案（五维 0-Token 确定性清标引擎）

### §3.1 独立核心模块：`core/bid_similarity.py`（100% 确定性计算为主，0 编造）

接收：`bid_files: list[dict[str, str | Path]]`（2~6 家投标书，含 `label` 如“单位A/B/C”与路径）+ 可选 `tender_path: Optional[str | Path]`（强烈推荐传入用于剥离招标公共文本）。

1. **维度 1 · 文件底层元数据与内嵌图哈希碰撞（铁证最先抓）**：
   - `.docx`：读取 ZIP 内 `docProps/core.xml`（`creator`、`lastModifiedBy`、`created`、`modified`、`revision`）及 `docProps/app.xml`（`Company`、`Application`），并计算 `word/media/*` 全部内嵌图片二进制 SHA256 集合；
   - `.pdf`：读取 PyMuPDF `doc.metadata`（`author`、`creator`、`producer`、`creationDate`、`modDate`）及去重后内嵌图片流 SHA256；
   - 判定规则：两份及以上标书出现相同的非通用 `creator / lastModifiedBy / author`（排除系统默认值如 `'Administrator'` 降级提醒、普通人名/域账号直接标 `error`）、或修订时间为同一分钟窗口 + 相同非常用图片哈希交集，输出明确证据卡片。
2. **维度 2 · 剥离招标底稿后的“净正文相似度”引擎（防误报核心）**：
   - 若传入 `tender_path`：对招标书提取规范化句子/短语与 12-gram 滑动切片黑名单 `tender_shingles`；并内置标书制式套话白名单（如“投标人名称（盖章）”“法定代表人或其委托代理人”等）；
   - 对每份投标书分段切片后**优先剔除命中 `tender_shingles` 或套话白名单的公共片段**，得到净自编文本 `net_text`；
   - 对任意两家 `(i, j)` 计算：
     - **净正文 8-gram Jaccard 相似度（`net_similarity_pct`）**：保留两位小数；给出风险分级（如 `<15%` 正常 / `15%~35%` `warning` / `≥35%` `error`）；
     - **连续相同长句明细（`shared_passages`）**：精确找出去除公共文本后两家仍连续一致 `≥25` 字的原句，附带两边的原文摘录、字符偏移及双轨页码（如有），供人工对照改写。
3. **维度 3 · 非标“指纹错误”与共性串名碰撞**：
   - 扫描两家投标书正文中是否同时残留同一个**不属于本项目/招标文件**的第三方单位名、外部项目编号，或出现同一处异常全半角乱码/生僻错字上下文。
4. **维度 4 · 关键人员/联系/业绩实体碰撞（隐私脱敏展示）**：
   - 提取手机号、身份证号、项目负责人姓名与类似业绩合同编号；发现跨单位雷同时报警 `ENTITY_COLLISION`（**身份证号/手机号仅展示前 3 后 4 位掩码，严守脱敏纪律**）。
5. **维度 5 · 报价规律性关联沙盒（100% `Decimal` 禁 `float`）**：
   - 提取各家投标总价（`bid_total`）及分项报价明细；
   - 精算两两总价差额/比值，若存在 ≥4 项同名或对齐分项之间比值完全恒定（`Decimal` 波动 `<0.001`）或等差间距高度一致（`std ≈ 0`），触发 `REGULAR_PRICE_RATIO` / `REGULAR_PRICE_DIFF` 预警。

### §3.2 数据层与后端接口（`/api/similarity` 第 12 组路由）

1. **新增 ORM 表 `similarity_reports`（`backend/models.py`，全库由 11 表演进至 12 表）**：

2. **后端路由 `backend/routers/similarity.py`（严格多租户隔离 + 写操作审计）**：
   - `POST /api/similarity/compare`：接收 `title`（可选）、可选 `tender_file` + `bid_files: list[UploadFile]`（强制校验 `2 <= len(bid_files) <= 6` 且扩展名为 `.docx/.pdf/.txt`，单文件大小护栏同现有上传）；保存至 `data/uploads/similarity/{tenant_id}/{report_id}/`，执行 `analyze_bid_similarity(...)` 落库并返回 `SimilarityReportDetailOut`；审计 `similarity_compare`；
   - `GET /api/similarity`：分页/列出当前租户历史防雷同对比记录；
   - `GET /api/similarity/{report_id}`：查看对比详情（跨租户严格 `404`）；
   - `GET /api/similarity/{report_id}/export`：导出可读《多标书交叉比对与相似度分析报告.docx》（含矩阵表、元数据碰撞表、连续雷同原文双栏对照及免责合规声明）；
   - `DELETE /api/similarity/{report_id}`：删库同时级联清理磁盘上传文件。
