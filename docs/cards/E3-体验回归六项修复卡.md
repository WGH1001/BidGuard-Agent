## 2. 交付物与验收标准

### 2.1 core/price_extractor.py（完整覆盖版）
- docx 表格路径加空白格式表防线：**行号序列形态**（数量/单价/合价 = 1/2/3 这类连续小整数、或单元格为空/省略号"…"）不得解析为报价行；列头词黑名单（`_HEADER_NAME_BLACKLIST`）在表格路径同样生效；
- 复现用例必须通过：名称为真实品目、数量/单价/合价恰为 1/2/3 的 docx 表 → `items == []` 且状态 `NEED_MANUAL`；
- PDF 文本路径零回归：11 份语料 price_cap 仍 11/11。

### 2.2 core/parser.py（完整覆盖版）
- 新增页码映射能力：PDF 优先读 page label（`page.get_label()`，即阅读器里显示的印刷页码），无 label 回退物理页号；docx 恒为 null；
- `parse_document` 既有签名与返回结构**一字不动**，新增能力以新函数/新可选参数提供；
- 禁止新增 pip 依赖。

### 2.3 core/tender_extractor.py（完整覆盖版）
- F1 四张清单的每条结果新增 `page` 字段（PDF 经 §2.2 映射取真页码；docx 为 null——前端已有 null 兜底显示字符偏移）；
- **碎片过滤**：单字/单词、无动宾语义的标记行（如"▲值回"）不得进入 requirement 清单——判定收紧但**不许误伤**正常短要求（以既有 89+5 项测试与 11 份语料 178 条要求为零回归底线，拿不准的降级 usage_note 而非删除）。

### 2.4 core/response_checker.py（完整覆盖版）
- 同文对齐加固：招标要求原文逐字存在于投标书时**必须直通命中**（0ms 门控），不得落入混合检索；
- 括号长句/分句形态的对齐漏检修复：目标=两份完全相同的 docx 跑 `run_response_check`，`MISSING_RESPONSE` 必须为 **0**；
- E2 的跨需求污染降级逻辑与 94 项既有测试零回归。

### 2.5 前端（三个文件完整覆盖版）
- `App.vue`：`<router-view>` 包 `<KeepAlive>`（include 视图组件名），切页保活；
- `ExtractView.vue`：组件名注册（保活生效的前提）；结果同时镜像一份到 sessionStorage（保活被手动刷新时兜底恢复）；进页面已有结果时**严禁重复触发提取**；页码展示用 `formatPageOrOffset` 最新三分支；
- `ModelSettingsView.vue`：API Key 输入框加 `autocomplete="new-password"`，消除浏览器保存密码弹窗。

### 2.6 测试（新建 tests/test_e3_fixes.py）
- 覆盖 §2.1 复现用例、§2.3 碎片过滤（"▲值回"不进清单 + 正常短要求不误伤）、§2.4 同文对齐零漏答、§2.2 页码映射（构造带/不带 page label 的 PDF）；
- 断言全部数数，严禁空循环假绿；mock docx 构造遵守"★行间插中性行"卡文铁律。
