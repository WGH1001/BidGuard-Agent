## 2. 需要写进文档的准确内容（实现者照此扩写，勿改技术事实）

### 2.1 F7 六大工具（位置：README F7 相关章节；同样内容后续可并入《标书知识扫盲》文档）

全部为**确定性函数**，LLM 只决定"何时调哪个、怎么解读结果"，工具本身零幻觉：

| # | 工具 | 职责 | 输入 → 输出 | 底层实现 |
|---|---|---|---|---|
| 1 | `search_tender` | 招标文件关键词检索 | 关键词 → ±200 字符原文窗口 + 字符偏移 + PDF 页码 | `_search_text_windows` 确定性定位 |
| 2 | `search_bid` | 投标文件关键词检索 | 同上 | 同上 |
| 3 | `locate_chapter` | 章节标题定位 | 章节关键词 → 章节起始偏移与页码 | 复用 `tender_extractor.locate_chapters` |
| 4 | `recalc_price` | 报价算术复算 | 分项清单 + 总价 → 沙盒核验 findings | F2 `PriceSandbox`（Decimal 0-Token） |
| 5 | `check_cert_expiry` | 证照效期/串名核验 | 证照文本 + 开标日 → findings | F3 `scan_qualifications`（0-Token） |
| 6 | `cite_regulation` | 权威法条检索 | 关键词 + 条号 → 条文原文 + 法律名 + 条号（库空诚实报"法规库为空"） | E4 法规库（大模型对法条真伪零裁决权） |

ReAct 循环最多 6 轮；`final` 动作的 quotes 强制过 `verify_quote()` 原文逐字核验，杜绝幻觉。无 Key 时自动降级 `keyword_fallback`。

### 2.2 三级自适应混合检索与 Rerank 原理（位置：README F4/检索相关章节）

- **触发门控**：85%+ 规范条款在 F4 初筛（条款号/标题/2-gram 重合度）0ms 直通，仅"疑似漏应答"与 F7 提问才进混合检索；
- **Level 1（0 Token，<3ms）**：纯 Python Okapi BM25（k1=1.5, b=0.75）+ 45 组招投标领域同义词双向扩展（如"质保期"↔"免费维保期"，同组命中映射共享概念 token 并给 2.2 倍 boost）+ 中文 2-gram 分词；
- **Level 2（有向量 Key 时激活）= Rerank 精排**：全文按行切块 → embedding 向量化（**SHA256 文件级缓存** `data/cache/{hash}.emb.npy`，同一文档只算一次）→ 余弦相似度粗筛 Top-15 → 与 BM25 得分**加权融合（0.55×向量余弦 + 0.45×BM25 归一化分）** → 精排取 Top-3。本质：把"字面匹配度"与"语义相似度"两个维度融合后重排序；
- **Level 3 兜底**：无 Key / 离线 / 网关异常 → 静默停留 Level 1，100% 零报错毫秒级返回。
