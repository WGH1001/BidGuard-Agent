## 1. 背景与实锤现象（语料算术全对，严禁改语料）

芜湖无为报价表（44 张表中）合计行首格填 **"--"**（序号列破折号），行名为 **"年度投标报价合计"**：

```
| -- | 年度投标报价合计 | 上述1、2项工作量按采购人年度预估任务量测算 | 三年（1+1+1模式） | ... | -- | -- | 679,200.00 元 |
```

`_SUMMARY_ROW_RE` / `_GRAND_TOTAL_ROW_RE`（core/price_extractor.py L164/L168 区）均为 **`^\s*(?:合计|总计|报价合计|投标总价|...)` 行首锚定**——首格 "--" 与"年度投标报价合计"（以"年度"开头）均不匹配任何前缀关键词 → 合计行被当**明细行**收集：items 多出 1 条（单价 679,200.00 × 数量 1），Σitems = 1,358,400 = 2×679,200 → 误报 `TOTAL_MISMATCH`（差 679,200）。

语料真实算术全对：0.35×300,000=105,000 + 0.33×1,740,000=574,200 = 679,200 ✓。"年度投标报价合计"是合法常见行名，**严禁改语料**。

## 2. 修复方案（core/price_extractor.py，E13 同族追加判定）

1. 汇总行识别增加**后缀匹配**：名称单元格文本以 `合计/小计/总报价/总价/投标总价` **结尾**（如"年度投标报价合计"、"报价总计"、"分项报价小计"）→ 判定为汇总行（grand_total 或 subtotal 按既有规则细分）；
2. 防误伤护栏（必须全部满足才判汇总行）：
   - 该行含 ≥1 个金额单元格，且金额与行内其他明细特征不冲突；
   - 行名不以动词开头且不含服务内容描述词（如"提供/开发/运维/培训"等 `说明：具体词表实现者结合 _INSTRUCTION_NOISE_KEYS 风格设计）；
   - 命中 `_INSTRUCTION_NOISE_KEYS`（不得超过/得分/计算公式等）的行绝不判汇总行（既有护栏保持）；
3. 前缀匹配逻辑**一字不动**（E7/E8/E9 既有行为零回归），本卡纯**追加**后缀分支。
