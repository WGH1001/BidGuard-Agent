# E22 · LLM 网关思考参数防御加固：组合拒绝识别 + 单实例熔断记忆 + 流式重试补漏 + 映射配置化

> 状态：待派发（建议 Gemini）｜ 立卡：2026-11-11 ｜ 基线：commit `9c06aa6`（167 项全绿）｜ 已定稿（Gemini 交叉审查 2 硬伤 4 细节修订采纳）
> 来源：E21 交付后架构侧会诊（多厂商思考参数适配咨询），按"先防御后适配"原则拆出的轻量加固卡；
> 四层 Provider Profile 全家桶（百炼/DeepSeek 路由等）**明确不在本卡范围**，待真实第二家厂商实弹接入时逐条补。

## 1. 背景与实锤（本卡三个真实缺陷，均已实机核实）

1. **`chat_stream()` 流式路径去参重试缺口（现存 bug）**：[`core/llm_gateway.py` L283-313](../../core/llm_gateway.py) 的 `except Exception` 分支虽会重发一次请求，但仅当 `base_kwargs.get('extra_body', {}).get('thinking')` 为真时才删掉整个 `extra_body`——若上游拒绝 `reasoning_effort`（或 `enable_thinking`、`thinking_budget`，无 `thinking` 键），重发时原封不动带着报错参数必继续失败；此外 L306 `except TypeError:`（`stream_options` 降级）位于 `except Exception` 之外，触发 `stream_options` 降级后再遇 400 拒参根本进不到重试，且 L284 `not self.use_openai` 回退分支调用 `self.chat(...)` 时漏传了 `reasoning_effort=reasoning_effort`。
2. **无熔断记忆，多轮循环反复撞墙**：`chat()` 每次调用都经 `_build_extra_body()` 重新构建参数（含 yaml 静态 `chat_options.reasoning_effort`），上游 400 拒参后剥参重试只救当次调用；F7 一次问答 7 轮 ReAct，**每轮都白打一次注定失败的请求**（已被拒一次即证明该模型不支持，后续轮次毫无理由再试）。
3. **裸关键词误伤风险**：现 `_is_thinking_reject()`（L94-101）为裸匹配 `'1210' or 'thinking'`，若简单扩成裸匹配 `'unsupported'`，会把 `"unsupported image type"`、`"unsupported model"` 等无关 400 误判为思考参数拒绝，掩盖真实错误并浪费重试。

**生命周期实锤（决定熔断形态，已核实）**：`get_llm_client()` 与 `build_client_from_user_config()` 均**无缓存、每次调用新建实例**，`resolve_effective_llm_client()`（`backend/worker.py` L286-321）每请求/每后台任务调一次——**一请求一实例**。故熔断记忆只需存活于单次请求（一次问答 2~7 轮 / 一次体检任务）内：第 1 次被拒 → 本请求后续轮次全部无参直发；下一个请求自然新实例自动重探，网关升级后下一请求立即恢复，**无需 TTL、严禁写库/写全局**。

## 2. 改动清单

### 2.1 `core/llm_gateway.py`（核心改造，两端统一 + 熔断）

1. **`_is_thinking_reject()` 升级为组合条件匹配**：
   - 判定规则：`(含思考参数关键词) AND (含拒绝/非法语义词)` 才返回 True；`'1210'` 保留为独立捷径（智谱参数错误码，单独命中即 True）；
   - 思考参数关键词：`reasoning_effort` / `enable_thinking` / `thinking` / `thinking_budget`；
   - 拒绝语义词：`invalid` / `unsupported` / `unknown` / `not support` / `unrecognized` / `unexpected keyword` / `extra fields` / `非法` / `无效` / `不支持` / `未知参数`（英文统一 casefold 后匹配）；
   - 反例必须为 False：`"unsupported image type"`、`"unsupported model"`（不含思考参数关键词）。
2. **抽出公共辅助函数供 `chat()`/`chat_stream()` 共用（严禁两份复制逻辑）**：
   - `_strip_thinking_params(extra_body: dict) -> dict`：剥除 `reasoning_effort` / `thinking` / `thinking_budget` / `enable_thinking` 键（**仅操作局部 `extra_body` 字典副本，严禁原地修改 `self.chat_options`**）；
   - `_mark_effort_unsupported()`：置 `self.supports_reasoning_effort = False`（复用 L90 现成开关属性，user-config 路径已存在该属性，env 路径 `getattr` 缺省 True）。
3. **`chat()` 补熔断记忆**：重试剥参成功路径上调用 `_mark_effort_unsupported()`——本请求后续轮次经 `_build_extra_body()` 与 L191 的 `getattr` 判断自然全程无参直发，一次问答只疼一次。
4. **`chat_stream()` 补齐同构去参重试**：
   - 抽出流式创建重试逻辑，兼容处理 `stream_options={'include_usage': True}` 触发的 `TypeError` 降级与 `_is_thinking_reject` 400 拒绝（即便先触发 `stream_options` `TypeError` 后再遇 400 拒参也能捕获剥参重试）；
   - 遇 `_is_thinking_reject(e)` 时调用 `_strip_thinking_params` + `_mark_effort_unsupported()` 并重试一次；**裸 500/网络类非思考参数异常直接上抛，不进无意义剥参重试**；
   - 顺带修补 L284 `if not self.use_openai:` 回退分支调用 `self.chat(...)` 时透传 `reasoning_effort=reasoning_effort`。
5. **`_build_extra_body()` 内部配置隔离 + 尊重熔断开关**：
   - **无条件剔除** `'max_tokens'` 与内部配置键 `'reasoning_effort_map'`，严禁将 `'reasoning_effort_map'` 透传进上游 HTTP `extra_body`（即使 `supports_reasoning_effort=True` 也绝不可透传）；
   - 当 `getattr(self, 'supports_reasoning_effort', True)` 为 False 时，同步跳过 `reasoning_effort`、`enable_thinking`、`thinking` 与 `thinking_budget`（→`thinking` dict 映射），防 yaml 静态配置绕过熔断。**注意**：env 路径实例无该属性时缺省 True，现有行为零变化。
6. **新增 `translate_reasoning_effort(value: str) -> Optional[str]`**：读 `self.chat_options.get('reasoning_effort_map')`（dict，键值均规范化小写）做 UI 值→上游值翻译；**当 `chat_options` 未配置 `reasoning_effort_map` 或当前 `value` 不在映射表中时，必须返回 `None`**（让调用方安全回退至 `_EFFORT_UPSTREAM_MAP`，严禁未配置时原样返回 `'medium'` 导致智谱 `400-1210` 复发）。

### 2.2 `core/bid_react_agent.py`（映射配置化）

- `_EFFORT_UPSTREAM_MAP` 保留为内置默认（`low/medium/high/max → low/high/max`，轮次上限 7 逻辑不动）；
- `_resolve_effort_and_rounds(reasoning_effort: Optional[str], max_rounds: int, client: Any = None)` 新增可选 `client=None` 形参（保持 2 参调用向后兼容，并在 `ask_bid_expert_stream` 调用处显式传入 `client=client`）；
- 先校验 `raw_key in _EFFORT_UPSTREAM_MAP`（非法值如 `'invalid'` 仍直接返回 `(None, base_limit)`）；命中合法挡位时，若 `client` 非 `None` 且具备 `translate_reasoning_effort`，优先取 `mapped = client.translate_reasoning_effort(raw_key)`，返回非空字符串即采用，返回 `None`/空时回退 `_EFFORT_UPSTREAM_MAP[raw_key][0]`——网关改合法枚举值从此只改 `models.yaml`，不发版代码。

### 2.3 `config/models.yaml`（注释示例，不改生效值）

- `envs.prod.chat_options` 下新增被注释的示例块 `# reasoning_effort_map: {low: low, medium: high, high: max}` 附两行说明（内网网关摸底后按实测填）；demo 环境不动。

### 2.4 `scripts/probe_reasoning_efforts.py`（新建，手动实弹探针）

- argparse 支持 `--env`（读 models.yaml 对应环境）与 `--base-url/--api-key/--model` 直连两种模式；
- 对候选值 `low / medium / high / max` 逐一发送最小 chat 请求（max_tokens=16），打印 `值 → HTTP 200/400 + 错误摘要` 矩阵，并顺带探测 `enable_thinking` 形状一次；
- **铁律：仅供人工在内网/有网环境手动运行，严禁被任何 pytest 用例 import 或 CI 调用**（延续 E4 外网隔离纪律）；输出日志严禁打印 `api_key` 明文；库代码严禁 print，本脚本属 CLI 工具允许输出。

### 2.5 `tests/test_e22_gateway_effort_adapter.py`（新建专项）

- ① 组合识别单测：上表正例（`reasoning_effort is not supported`、`1210`、`enable_thinking unknown parameter`、`无效的 reasoning_effort 参数`）为 True，反例（`unsupported image type`、`unsupported model`、纯 500 网络文案）为 False；
- ② 同步熔断：Mock 上游首次 400（含 `reasoning_effort ... invalid`）→ `chat()` 剥参重试成功，且同实例第二次 `chat()` **首次请求即无参**（Mock 断言收到的 extra_body 键）；
- ③ 流式补漏回归：同 ② 场景（含先遇 `stream_options` `TypeError` 再遇 `reasoning_effort` 400 场景）下 `chat_stream()` 重试成功且熔断生效；而裸 500 网络异常直接上抛不进剥参重试；
- ④ `_build_extra_body()` 内部配置隔离与熔断跳过：无论 `supports_reasoning_effort` 为 True 或 False，`reasoning_effort_map` 绝不进入 `extra_body`；`supports_reasoning_effort=False` 时 yaml 配了 `reasoning_effort` / `enable_thinking` / `thinking_budget` 也不进 `extra_body`；缺省（无属性）行为与现状逐键一致；
- ⑤ 映射配置化：`chat_options` 带 `reasoning_effort_map` 时 `translate_reasoning_effort` 按配置翻译并在 `_resolve_effort_and_rounds(..., client=client)` 生效；**未配置 `reasoning_effort_map` 时 `translate_reasoning_effort('medium')` 返回 `None`**，`bid_react_agent` 回退内置映射仍得 `('high', 7)`（2 参老调用与非法挡位 `'invalid'` 兼容不变）。

## 3. 验收标准

1. 新增专项测试全绿 + 全量 `pytest tests/ -q`（基线 167 项 + 新增）零回归全绿；
2. 本卡零前端改动，`npm run build` 非必需（如跑需通过）；
3. 实弹对账（有条件时）：`scripts/probe_reasoning_efforts.py --env prod` 在公司内网实跑一次，输出四值矩阵贴回卡归档（无内网环境可延后，不阻塞入库）；
4. `config/models.yaml` 经 `yaml.safe_load` 校验无语法错误。

## 4. 铁律与文件白名单

- 熔断记忆**只许**存活于 `LLMClient` 实例内存：严禁写数据库、严禁模块级/全局变量、严禁 TTL 定时器（一请求一实例已实测，TTL 纯冗余）；
- **F4 并发线程安全**：严禁原地修改 `self.chat_options`（`_strip_thinking_params` 只能操作 `_build_extra_body()` 返回的局部副本，防 4 线程并发共用同一 `LLMClient` 时字典迭代异常）；
- 严禁改动 `backend/worker.py` 的客户端生命周期（一请求一实例是熔断正确性的前提）；
- 严禁改动前端任何文件与 `core/bid_react_agent.py` 的 ReAct 主循环/工具白名单逻辑（本卡只碰映射解析一小段）；
- `chat()`/`chat_stream()` 既有签名、返回结构与 167 项既有测试零回归；`_is_thinking_reject` 原函数名保留（外部有引用）；
- 探针脚本严禁被 pytest/CI 引用；库模块静默（不 print）；全程 `encoding='utf-8'` + `newline='\n'`；
- 文件白名单：`core/llm_gateway.py`、`core/bid_react_agent.py`（仅 `_resolve_effort_and_rounds` 与映射常量段）、`config/models.yaml`（仅注释）、`scripts/probe_reasoning_efforts.py`（新增）、`tests/test_e22_gateway_effort_adapter.py`（新增）。
