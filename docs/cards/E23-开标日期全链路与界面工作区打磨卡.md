# E23 · 开标日期全链路精准提取、大盘/F5/F7工作区扩屏与工具解包修复卡

> 状态：待派发（建议 Gemini）｜ 立卡：2026-11-11 ｜ 基线：commit `e5170f8`（184 项全绿）｜ 已定稿（架构侧实锤复核通过：7/11 漏检、规则日抢答覆盖、字符串 action_input 误拒、total_price 缺失按 0 误算均独立复跑属实）
> 来源：用户全链路 UI 走查与真实语料实测反馈（7 份标书漏抓开标日期 / F1 与 F6 无开标日 / 大盘倒计时缺 F6 标识且固定 5 条 / F5 首次进页全白遮罩 / F7 对话框太扁且深度按钮偏高 / 顶部全局导航栏冗繁 / `recalc_price` 字符串参数报错）。

## 1. 问题实锤与根因清单

1. **开标日期抽取 7/11 真语料漏检（已用 11 份 `m0_samples` 实跑实锤）**：
   - 现 [`backend/worker.py`](../../backend/worker.py) 的 `_OPEN_DATE_EXTRACT_RE` 含 `r'[^\d\n]{0,28}?'`，一旦 `"提交投标文件截止时间、开标时间和地点"` 与日期之间夹有换行 `\n`、序号 `1.`（如 `JSZC-0484 江苏科技`：`地点\n1.2026年10月16日`）、或 PDF 跨页页码 `\n5\n`（`芜湖无为`），正则直接漏抓（实测 11 份漏 7 份）；
   - `worker.py` L498 优先读取租户默认规则的预置演示日（`2026-11-05`），直接跳过标书原文自动识别；
   - F1（`extract.py` / `ExtractChecklistOut`）与 F6（`radar.py` / `RadarScanOut`）完全未接入开标日期提取，导致大盘倒计时里所有 F6 均显示`待设定`。
2. **大盘展示与文案滞后（[`DashboardView.vue`](../../frontend/src/views/DashboardView.vue) / [`dashboard.py`](../../backend/routers/dashboard.py)）**：
   - `countdown_alerts` 按 `id` 倒序硬截前 5 条，无日期的 F6 会把有真实截标倒计时的项目顶出榜单；且前端未渲染后端已下发的 `task_type` 区分`双书体检 / F6 雷达`；
   - 底部台账副标题仍写 `F1~F4`，未体现已同表展示的 `F6 控标雷达`（不混入无状态 F1 单书拆解历史，保留 `#id` 编号）。
3. **F5 首次进页全白转圈（[`DeviationView.vue`](../../frontend/src/views/DeviationView.vue)）**：
   - `v-loading="generating"` 挂在整页根节点上，当 `devResult === null` 首次同步生成偏离表时，白色遮罩将顶部工具栏一起糊白只剩转圈。
4. **全局顶栏占高冗繁 & F7 对话区视口占比过低（[`App.vue`](../../frontend/src/App.vue) / [`QaChatView.vue`](../../frontend/src/views/QaChatView.vue) / [`QaMessageList.vue`](../../frontend/src/components/QaMessageList.vue)）**：
   - `.bg-topbar` 高 60px 且重复放了侧栏/大盘已有的两个跳转按钮（`+ 发起封标防废标体检`、`投前控标雷达`）以及重复的 `系统管理员 系统管理员` 标签；
   - F7 右侧面板顶部 `.qst-header` 占两行（含推理深度条）+ 底部 `快捷追问` 占两行，使 `.msg-scroll-area` 垂直空间被压缩到不足半屏，长回答需反复滚轮，且三挡推理深度放在最顶部离发送按钮太远。
5. **F7 `recalc_price` 等工具调用对字符串化 JSON 报错（[`core/bid_react_agent.py`](../../core/bid_react_agent.py)）**：
   - 实测截图显示 LLM 输出 `"action_input": "{\"items\": ...}"`（字符串化 JSON）时，`bid_react_agent.py` L681 只认 `dict`/`list`，直接报 `{"error": "recalc_price 需要 items 列表"}`；且当 `items` 缺省 `total_price` 时 `PriceSandbox` 默认作 `0` 易误报算术差错。

## 2. 改动清单

### 2.1 `core/tender_extractor.py` + `backend/worker.py` + F1/F6 统一开标日期

1. **下沉并升级 `extract_open_date_from_tender_text(text: str) -> Optional[str]` 至 `core/tender_extractor.py`**：
   - 放开锚点词与日期之间跨换行（`\n`）、标点、列表序号（`1.`/`（1）`）、`时间：` 及 PDF 短页码数字；
   - 排除资格条件与招标文件获取时间等非开标日干扰句（如 `"提交投标文件截止时间前一年内"`、`"至"` 区间前半段）；
   - `backend/worker.py` 改为 `from core.tender_extractor import extract_open_date_from_tender_text` 保留原模块名导出兼容既有单测；
   - **硬验收指标**：仓内 `data/corpus/m0_samples/` **11 份真实招标书 11/11 全命中**且日期准确。
2. **接入 F1 与 F6**：
   - `build_review_checklist()` 返回新增 `'open_date': extract_open_date_from_tender_text(text)`；`ExtractChecklistOut`（前后端类型）新增可选 `open_date?: string | null`，`ExtractView.vue` 结果概览条展示`开标日期`；
   - `backend/routers/radar.py` 扫描时调用 `extract_open_date_from_tender_text`，命中则存入 `task.config_json = {'open_date': detected}` 并在 `RadarScanOut` 可选返回 `open_date`，`RadarView.vue` 结论横幅一并展示；
   - `backend/worker.py`（F2~F4）优先级改为：**任务创建手填 `cfg_snap['open_date']` > 标书全文自动提取 > 规则页 `rule_cfg.open_date` > `DEFAULT_FALLBACK_OPEN_DATE`**（不再让默认规则日期屏蔽标书原文提取）。

### 2.2 大盘优化（`backend/routers/dashboard.py` + `DashboardView.vue`）

1. **`dashboard.py` 倒计时列表**：
   - F6（`radar`）不盲借 `pre_check` 的租户规则默认日期（优先读 `t.config_json.get('open_date')`，无则保持 `None` 显示 `待设定`）；
   - `countdown_alerts` 优先将**已有 `open_date` 的项目**按临近截标/最新倒序置顶，其次附最近 `open_date=None` 任务，上限放宽至 **8 条**（前端列表限高内滚动）。
2. **`DashboardView.vue`**：
   - 右侧倒计时每行左侧标题/元信息旁渲染 `task_type` 徽标（`双书体检` / `F6 雷达`），F6 零命中标签用 `零排他项` 与双书 `零否决项` 区分；
   - 底部台账副标题更新为：`实时汇总 F1~F5 封标防废标体检与 F6 投前控标雷达记录，支持直达详情、导出偏离表或交付打包`（保留 `#id` 编号列，不塞入无状态 F1 单书拆解历史）。

### 2.3 F5 去全白遮罩（`frontend/src/views/DeviationView.vue`）

- 将 `v-loading="generating"` 从 `.deviation-page` 外层下移至下方内容包装区（保留顶部选择任务下拉框、重新生成与下载按钮始终可见可用）；首次无 `devResult` 且正在生成时展示明确的卡片提示文案（“正在消费 F4 核验结果生成标准偏离表…”），不再整页糊白。

### 2.4 全局顶栏瘦身 + F7 扩屏 + 发送旁深度选择器 + `recalc_price` 解包（`App.vue`、`QaChatView.vue`、`QaMessageList.vue`、`core/bid_react_agent.py`）

1. **`App.vue` 顶部压缩**：
   - `.bg-topbar` 高度由 `60px` 收紧至 `44px`，移除右侧冗余的 `+ 发起封标防废标体检` 与 `投前控标雷达` 按钮（大盘与左侧主导航已有清晰入口）；`.tb-user-chip` 当显示名与角色名相同时不重复渲染两次；`.bg-content-canvas` 上下 padding 调整为 `14px 20px`。
2. **`QaChatView.vue` & `QaMessageList.vue`（F7 聊天工作台高屏占比 + 发送旁三挡选择器）**：
   - `.qa-chat-layout` 调整为 `height: calc(100vh - 76px)`；右侧 `.qst-header` 压缩为单行紧凑标题（44px 左右，长说明缩为 hover 提示）；
   - 将三挡深度选择器（`⚡ 极速` / `⚖ 均衡` / `🧠 深度`）从顶部迁至输入区操作行（发送按钮左侧），点击弹出三挡选择菜单（带“快响应/默认均衡/Max 深度，均开放 7 轮 6 工具”简短说明），选择后照常持久化 `localStorage`；
   - `快捷追问`：空会话（`messages.length === 0`）时一行/多芯片展开，一旦开始对话（`messages.length > 0`）自动折叠为发送栏旁一个 `"💡 快捷追问 ▾"` 弹出按钮，释放底部约 `60px+` 高度；
   - 输入框改为自适应高度（1~4 行），消息区气泡放宽至 `max-width: 92%` 提升长回答一屏阅读量。
3. **`core/bid_react_agent.py` 工具参数兼容修补**：
   - 在工具分发前新增安全辅助 `_coerce_action_input(action_input)`：若大模型传回 JSON 字符串（`isinstance(action_input, str)` 且以 `{` / `[` 开头），先尝试 `json.loads` 解析为对象，彻底修复 `recalc_price` / `check_cert_expiry` / `cite_regulation` / `locate_chapter` 被字符串化参数误拒问题；
   - 同步在 `_REACT_SYSTEM_PROMPT` 与 `recalc_price` 报错提示中写明 `items` 规范字段（含 `qty`、`unit_price`、`total_price`），若缺失 `total_price` 明确提示缺少该字段而不悄悄按 0 误算。
