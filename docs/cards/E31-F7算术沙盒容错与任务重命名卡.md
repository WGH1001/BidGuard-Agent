## 1. 实测定位的根因与盲区清单

1. **`core/price_sandbox.py` 裸 `Decimal` 解析炸流（且严禁反向导入 `price_extractor`）**：
   - `amount_to_upper()`（L48）与 `_to_decimal()`（L104）直接执行 `Decimal(str(...))`；当 F7 `recalc_price` 将大模型从 OCR/标书中摘录的原始字符串（如 `"1,400,000元"`、`"140万元"`、`"1套"`、`"-"`）喂入 `PriceSandbox` 时直接抛出 `InvalidOperation` 炸断整条流；
   - 注：`core/price_extractor.py` L55 顶层已存在 `from core.price_sandbox import PriceSandbox`，`price_sandbox.py` 严禁反过来导入 `price_extractor`，必须在 `price_sandbox.py` 内实现零外部依赖的安全解析。
2. **`core/bid_react_agent.py` 工具分发裸奔与参数脆性**：
   - 7 工具分发块（L1120–1223）缺少单工具 `try ... except Exception:` 隔离，任一工具内部异常直接中断整条 SSE 生成器；
   - `search_tender` / `search_bid` / `search_attachment` / `locate_chapter` 中的 `int(action_input.get('after_offset') or 0)` 遇到非纯数字字符串会直接抛 `ValueError`；
   - `recalc_price`（L414–436）未兼容大模型常见的中英文字段别名（如 `price`/`单价`、`quantity`/`数量`、`amount`/`合价`）及 `qty=1` 时仅传 `unit_price`/`total_price` 之一的场景。
3. **前后端错误归类一刀切甩锅网关**：
   - `frontend/src/views/QaChatView.vue`（L854、L856、L891）与 `backend/routers/qa.py`（L688–699）将所有异常一律展示/包装为 `"模型网关响应超时或连接中断"`，掩盖了工具计算与参数解析类内部故障的真实报错。
4. **体检任务重命名缺口（Q1）**：
   - `backend/routers/checks.py` L216 创建任务未填标题时默认取投标文件名去后缀（如 `#45 安易—04包-工业物性数据应用开发平台`），目前缺少 `PATCH /api/checks/{task_id}` 重命名接口与台账/详情前端改名入口。

## 2. 改动清单（4 块）

### 2.1 `core/price_sandbox.py` 零依赖安全解析与结构化 `INVALID_PRICE_FORMAT`

1. **零外部依赖安全解析函数**（不引入 `price_extractor`）：
   - `_parse_sandbox_amount(val)`：清洗千分位逗号、空白、`￥/¥/人民币` 等货币修饰，识别 `"万元"/"万"` 并乘以 `Decimal('10000')`，剥离尾缀 `"元/圆/整/正"` 后转 `Decimal` 并按 `ROUND_HALF_UP` 量化至 `0.01`；空值与占位符（`""`、`"-"`、`"—"`、`"无"`、`"null"`、`"None"`、`"待定"`）视作缺失 `None`；
   - `_parse_sandbox_qty(val)`：清洗千分位逗号与常见计量单位后缀（`套/台/项/个/批/人月/年/个月/式/系统/节点/点位/页/条/卷` 等）及简单中文数字后转正数 `Decimal`。
2. **结构化报错不抛异常**：
   - 对可选汇总锚点（`table_total`、`bid_total`、`price_cap`），占位符或空串安全归一为 `None`；若传入无法解析的非占位字符串（如 `"待定文本123abc"`），产出 `code='INVALID_PRICE_FORMAT'`、`severity='error'` 的结构化 finding（指明具体字段名与原始值），不抛 `InvalidOperation`；
   - 遍历 `self.items` 时，若单行 `qty`、`unit_price` 或 `total_price` 无法解析为有效数字，为该行产出明确的 `INVALID_PRICE_FORMAT` error finding（含分项序号、名称、问题字段与原始值）并跳过该行算术乘加，继续核验其余分项与总价/限价；
   - `amount_to_upper(amount)` 同步改走安全解析；遇不可解析输入抛出清晰 `ValueError` 或由上层调用点（`PriceSandbox.run()`）提前拦截，避免 `Decimal.ConversionSyntax` 外泄。

### 2.2 `core/bid_react_agent.py` ReAct 单工具异常隔离自愈与 `recalc_price` 别名增强

1. **增强 `recalc_price`（L399–445）**：
   - 兼容模型常见字段别名：`name` / `item_name` / `名称`；`qty` / `quantity` / `count` / `数量`（缺省默认 `'1'`）；`unit_price` / `price` / `单价`；`total_price` / `amount` / `subtotal` / `合价` / `金额`；
   - 当 `qty == 1` 且仅提供 `unit_price` 与 `total_price` 之一时，自动按已知值补全缺失一侧（避免因只给出单价或只给出合价而无谓报错），且**必须在 `observation` 中显式标注 `derived: True`、`derived_fields` 与 `derived_warning`**（防止模型把推算值当成“标书原文写明”转述给用户，守住溯源铁律）；
   - 返回结果补充 `sum_of_items` 与 `item_count` 汇总字段，方便模型在多步问答中直观校对分项之和。
2. **安全整型偏移解析**：新增 `_safe_int_offset(val) -> int` 替换 4 处裸 `int(action_input.get('after_offset') or 0)`，非法值安全回退 `0`。
3. **单工具执行 `try / except Exception:` 隔离自愈**：
   - 在 `ask_bid_expert_stream`（L1119–1223）工具分发外层统一捕获 `Exception as tool_exc`（**不吞 `BaseException`**，确保外部中断信号正常透传）；
   - 将异常转化为结构化 `observation = {'passed': False, 'error': f"工具 {action} 执行异常（{type(tool_exc).__name__}: {tool_exc}），请检查并修正输入参数格式后重试"}`，正常 `yield {'type': 'step', ...}` 并回喂模型在下一轮自我修正（不中断整条 SSE 流）。

### 2.3 `backend/routers/qa.py` + `frontend/src/views/QaChatView.vue` 错误归类解耦

1. **后端区分异常来源**（[backend/routers/qa.py](file:///e:/agent/BidGuard-Agent/backend/routers/qa.py) L688–699）：
   - 增加轻量错误归类辅助函数，识别连接/超时/HTTP 状态/网关拒绝等真网关异常（继续返回 `502 QA_GATEWAY_ERROR`），而工具计算或内部代码异常不再套用“请排查 TUN 代理/网关连通性”文案，改为 `500 QA_EXECUTION_ERROR` 并透出真实异常类型与摘要；
   - `ask_in_session_stream` 的 `error` 事件帧同步携带规范 `detail` 与 `error_type`（`'gateway' | 'tool_or_internal'`）。
