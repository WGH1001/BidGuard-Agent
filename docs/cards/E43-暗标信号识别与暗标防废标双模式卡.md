# E43 · 暗标信号识别与暗标防废标双模式卡（优先于 E42 执行）

> 状态：已实现并全量验收（工作区待确认 commit）｜ 代码基线：E41 `960c995`（325 项基线 → E43 **330 项 pytest 全绿** + `vite build` 1865 模块零错误，`components.d.ts` 零改动，14 表 / 13 组路由 / 15 视图）
> 领导需求与竞品补齐：**业务 1「废标项识别」暗标防线深化 + 对标 WPS「暗标识别 + 暗标 6 项屏蔽生成」**，拆除 F8（`export_composed_bid_docx`）面对暗标项目的“一秒废标炸弹”。
> 统筹衔接声明（E43 → E42）：本卡产出 F1 `blind_bid_info` 与体检阶段 `BLIND_BID_IDENTITY_LEAK` / `BLIND_BID_STYLE_VIOLATION` 发现（`consequence='veto'`），供下一张 **E42 评分预估卡** 直接消费为一票否决/重度扣分预警信号。

---

## 1. 核心目标

1. **招标侧暗标红线确定性提取（0 Token）**：在 `core/tender_extractor.py` 新增 `extract_blind_bid_requirements()`，精准识别招标文件中关于技术标暗标的强制禁令（禁止投标人名称/人名/Logo/联系方式、禁止底纹/阴影/加粗/斜体/下划线/边框、目录限制及字体行距统一要求），每条附带原文 `quote`、条款号与双轨页码出处，F1 与体检页高亮警示。
2. **体检侧暗标违规筛查（0 Token + 为 E42 供血）**：当双书体检任务识别到招标书包含暗标要求时，确定性扫描投标文件正文、`.docx` 页眉/页脚/内嵌图片以及格式底纹加粗标记，检出直接输出 `BLIND_BID_IDENTITY_LEAK` / `BLIND_BID_STYLE_VIOLATION`（`severity='error'`, `consequence='veto'`）。
3. **F8 生成侧「通用 vs 暗标」双模式 + 素颜渲染 + 6 项脱敏规则 + 自定义屏蔽词**：
   - 蓝图装配与 AI 撰稿增加 `blind_bid_mode`、6 项标准屏蔽开关（投标人/单位名称、Logo/商标/水印及证照实图、人员真实姓名、联系方式/地址/邮箱、非本项目名称编号、历史项目或业绩案例）及自定义屏蔽词列表；
   - Word 导出层严格执行**素颜暗标渲染**：去独立装饰封面（改为纯文本匿名盲审题头或跳过封面）、清零页眉页脚、按招标目录禁令自动剥离 TOC 目录、清零所有表格底纹（`_shade_cell` 跳过）与加粗/斜体/下划线/高亮底色，且证照附页不嵌入带公章/Logo 扫描图片。

## 2. 技术设计明细

### §2.1 识别与体检层（`core/tender_extractor.py` + `core/qualification_scanner.py` + `backend/worker.py`）
1. **`core/tender_extractor.py::extract_blind_bid_requirements(text, *, page_ctx=None) -> dict[str, Any]`**：
   - 纯正则 0-Token 扫描「暗标」「盲标」「匿名评审」「不得出现投标人」「不得使用底纹/阴影/加粗/斜体/下划线/边框」「禁止设置目录/目录限制」「不得体现公司名称/人员姓名/Logo」等上下文段落，并过滤普通条款中的非暗标干扰（如“非暗标项目”否定句）；
   - 返回 `{ 'is_blind_bid': bool, 'requirements': [{'rule_type': 'no_identity'|'no_special_style'|'toc_policy'|'format_constraint', 'clause_no', 'quote', 'quote_verified': True, 'offset', 'page', 'summary'}], 'recommended_rules': [...], 'toc_forbidden': bool, 'style_forbidden': bool }`；
   - 接入 `build_review_checklist()` 返回键 `'blind_bid_info'`；同步扩展 `backend/schemas.py::ExtractChecklistOut` 与 `backend/routers/extract.py` 透出 `blind_bid_info`。
2. **`core/qualification_scanner.py::scan_blind_bid_compliance(bid_path_or_text, blind_bid_info, *, bidder_hints=None, custom_words=None) -> list[dict]`**：
   - 当 `blind_bid_info.get('is_blind_bid')` 为 True 时执行确定性筛查：
     - 身份泄露（`BLIND_BID_IDENTITY_LEAK`）：检测正文或 `.docx` 页眉/页脚中出现的 `forbidden_names`/疑似投标人全称/联系人手机号/邮箱，每条过 `verify_quote` 核验并带出页码/偏移；`bidder_hints` 来源 = 租户机构名 + 企业证照台账主体名 + 用户自定义屏蔽词；
     - 图片违禁（并入 `BLIND_BID_IDENTITY_LEAK` 或单列 `BLIND_BID_MEDIA_FORBIDDEN`）：**仅当招标明令"不得出现图片/图像/插图"时**按 `.docx` `word/media/` 非空确定性判违禁；若招标仅要求"禁 Logo/带公章图片"而无全面禁图，0 Token 无视觉识别能力，**诚实降级为 NEED_MANUAL 人工核查提示**（铁律 4 宁缺毋滥，绝不猜测图片内容）；
     - 格式违禁（`BLIND_BID_STYLE_VIOLATION`）：检测 `.docx` 中违反招标"不得使用底纹/加粗/斜体/下划线/目录"的 Run 样式、底纹节点（`w:shd`）或 TOC 目录存在性。
   - `backend/worker.py::_run_pipeline` 在 Stage 2（F3 阶段尾部）调用 `scan_blind_bid_compliance`，将检出发现入库 `BidFinding`（**`source_module='BLIND_BID'`**——`models.py` 该列为 `String(16)` 自由串，不占用 F3 语义；同步更新列注释），`consequence='veto'`，零破坏现有流水线。
   - **保守清理边界**：`_apply_blind_bid_sanitization` 仅对可确定性识别的线索做精确替换（`forbidden_names` 全称、`custom_words` 精确匹配、手机号/邮箱正则）；**无法确定性判定"非本项目"的外部项目编号/业绩案例线索不强改文本**，降级 NEED_MANUAL 提示人工处理（防误伤合法引用）。

### §2.2 F8 暗标编制与导出层（`core/bid_composer.py` + `backend/routers/composer.py`）
1. **蓝图与脱敏过滤 (`compose_bid_blueprint`)**：
   - 新增可选参数（默认值完全向后兼容 E37~E41）：`blind_bid_mode: bool = False`、`blind_rules: Optional[list[str]] = None`、`blind_custom_words: Optional[list[str]] = None`；
   - 新增 6 项标准规则映射表 `_BLIND_RULE_KEYS`：`hide_bidder_name`、`hide_logo_media`、`hide_person_name`、`hide_contact_info`、`hide_external_project`、`hide_past_cases`，并支持 `blind_custom_words` 精确匹配；
   - 新增确定性清理函数 `_apply_blind_bid_sanitization(text, active_rules, custom_words, *, allowed_project_name='', allowed_project_code='') -> str`：无论 AI 是否遵守 Prompt，导出进 `BidBlueprint` 段落与表格单元格前均再次确定性匿名化（如替换为 `[按暗标要求已隐去]`），防模型漏网；
   - 若 `blind_bid_mode=True` 且 `hide_logo_media` 启用，Section 2（`qualification_checklist`）不关联嵌入任何带公章/Logo 的台账图片路径，改用文字声明「按暗标规定技术标内隐去企业证照扫描件，原件见资格审查文件」，同时在蓝图记录 `blind_bid_applied` 与 `blind_bid_info`。
2. **Word 素颜渲染 (`export_composed_bid_docx`)**：
   - 当 `bp.get('blind_bid_mode')` 为 True 时，强制切换为素颜盲审排版：
     - **封面**：不渲染带投标人落款/彩色徽标的独立封面页（仅可选输出居中纯黑无修饰题头《技术响应文件（暗标匿名版）》后直入正文）；
     - **页眉页脚**：`different_first_page_header_footer` 下全部置空不写项目名称与公司提示；
     - **目录（TOC）**：若招标要求 `toc_forbidden=True` 或未开启目录，跳过目录页与 `TOC \o` 域，避免下载后忘记手动删目录废标；
     - **去特殊样式标记**：`_shade_cell` 在暗标模式下不写任何底纹填充；`_set_run_font` 强制 `color=RGBColor(0x00, 0x00, 0x00)`、`bold=False`、`italic=False`、`underline=False`，清除手动黄色高亮背景，仅保留统一规范字号与黑色标准网格线；
     - 第一部分中 `投标人名称`、`法定代表人` 落款栏位按暗标隐藏不打印具体主体线索。
3. **API 接线 (`backend/routers/composer.py` + `backend/schemas.py`)**：
   - `POST /api/composer/generate` 新增表单入参：`blind_bid_mode: bool = Form(default=False)`、`blind_rules_json: Optional[str] = Form(default=None)`、`blind_custom_words_json: Optional[str] = Form(default=None)`；
   - 蓝图 `stats_json` 与 `ComposeDraftSummaryOut` 新增 `blind_bid_mode: bool = False` 标记，审计日志同步记录（严禁记录自定义敏感词明文，仅记规则键与脱敏数量）。
