## 1. 背景与目标

E33 已解决"查证效率"（并行工具 + 早停），本卡解决"该不该查证"的入口分流：

- **现状**：所有提问一律进 ReAct 检索循环——"你能干什么""把上一轮结果整理成表格"这类元问题也空跑检索轮次，烧 Token 也拖慢响应。
- **定位红线（产品语义）**：本卡预写的是"什么情况允许不查证"的**规则与护栏**，不是预写答案的 FAQ 词表——答案永远由模型现场生成；凡涉及**本项目**文件核验的问题，结论必须出自标书原文，绝不放水。

## 3. 改动设计

### §3.1 提示词扩展（`_REACT_SYSTEM_PROMPT`）

第 8 条 final 之后追加**快速通道**说明：允许**第 1 轮直接 final、零工具调用**，仅限三类：

1. 系统能力咨询（你能查什么 / 某工具怎么用 / 结果里的标签什么含义）；
2. 通用招投标法规与流程**概念题**（不涉及本项目文件内容，如"质疑期限一般是几天"）；
3. 仅对会话历史已有结果做**重排/整理/格式转换**（"把上一轮结果整理成对比表格"）。

直答时 action_input 增加可选声明 `"route": "direct_meta"`；`quotes` 留空（若引用历史消息中已验证的原文则必须逐字）。

**明令禁止直答的问题类型**（必须检索）：金额/限价/报价、质保期/工期/交货期、资质/社保/证照、★/▲/偏离、开标时间、本项目任何条款的响应情况。

### §3.2 Python 确定性回弹护栏（防偷懒，不依赖模型自觉）

- 新增 `_PROJECT_VERIFY_SIGNAL_RE`：`金额|限价|报价|质保|保修|工期|交货|资质|社保|证照|偏离|★|▲|开标|投标文件|招标文件|违约|废标|第[一二三四五六七八九十百\d]+条` 等；
- 新增硬参数 **`MAX_UNGROUNDED_BOUNCE_PER_TURN = 1`**（模块级常量，回弹上限绝不可调大）；
- **拦截条件**（全部满足才弹回）：
  1. `r_idx == 1` 且 `r_idx < limit`（`max_rounds >= 2`，避免单轮上限下弹回无下轮可执行）；
  2. `len(steps) == 0` 且 `fast_path_bounced is False`；
  3. 当轮无附件图片（`not norm_atts`）；
  4. 模型第 1 轮企图直接结束（无论输出结构化 `action='final'` 且未附经 `verify_quote` 核验的原文引用，还是在 `L1419` 输出非残缺工具 JSON 的纯文本裸答）；
  5. 用户问题命中 `_PROJECT_VERIFY_SIGNAL_RE`；
  6. **非合法历史重排指令**：仅当 **`bool(prior_history)` 为真** 且问题包含`"整理/上一轮/刚才/上述/转成表格/汇总"`等元指令时才免弹（防止空会话首问`"把投标文件报价整理成表格"`借元词绕过核验）。
- **弹回动作**：该轮不计 steps、不产 done；置 `fast_path_bounced = True`，向 `messages` 回灌纠正提示（"检测到问题涉及本项目文件核验，当前未调用任何检索工具，请先检索原文再作答"），进入下一轮；
- **封顶放行**：回弹后模型若仍直答 → **放行**，按未溯源呈现（`grounded=False`），严禁无限压制元问题；
- 护栏位于 LLM 输出解析层，与 E31 工具自愈 / E30 `BaseException` 透传（工具分发层）无交集，不得破坏两者语义；
- 回弹轮次**计入 limit**（第 1 轮被弹回后剩 limit-1 轮检索）；`rounds_used` 语义维持 E33 的"思考回合数"。

### §3.3 done 契约、落库透传与前端未溯源标签

- 直答被接受时（`len(tool_steps) == 0` 且无有效 `verified_quotes`，含非 JSON 纯文本首轮裸答）done 帧新增：`grounded: False`、`fast_path: True`、可选 `route`（模型声明时透传如 `'direct_meta'`）；`quotes` 强制为空或仅保留经 `_verify_and_locate_quotes` 逐字核验通过的历史原文；
- 正常检索路径（有工具检索步骤或 `keyword_fallback`）done 帧标 `grounded: True`、`fast_path: False`；**字段可选、缺省视为 grounded**，保持正文 `answer` 纯净不掺额外拼接文案，仅靠结构化字段驱动标签呈现；
- 后端必改透传（不改数据库表结构，复用 `messages_json`）：
  - `backend/schemas.py`：`QaAskResponseOut` 新增可选 `grounded: bool = True`、`fast_path: bool = False`、`route: Optional[str] = None`；
  - `backend/routers/qa.py`：`/ask` 返回、`ask_in_session_stream` `done_payload` 及 `_persist_qa_turn_locked` 写入 `messages_json` 的 assistant 条目均透传 `grounded` / `fast_path` / `route`，确保刷新页面或切换会话后标签不丢失；
- 前端：`types.ts` 的 `QaMessageItem` 与 `QaAskResponseOut` 增加可选 `grounded?: boolean; fast_path?: boolean; route?: string`；`QaChatView.vue` `onDone`（`L812`）与 `qaApi.ask` 兜底（`L931`）同步透传进消息对象；`QaMessageList.vue` 仅当 `msg.grounded === false` 时在消息头部渲染 warning 微标签「未检索标书原文 · 仅供参考」，正常回答**不显示任何新元素**。

### §3.4 与既有机制的交互

| 机制 | 关系 |
|---|---|
| E32 收口轮（limit 耗尽强制收口） | 无交集——回弹只作用于第 1 轮且仅 1 次 |
| E33 并行 actions | 第 1 轮输出并行工具调用即有 steps，天然不触发护栏 |
| E33 停滞遥测 | 直答路径无工具轮次，不注入遥测 |
| keyword_fallback（client=None） | 不走本卡逻辑 |

## 5. 测试清单（test_e34_react_fast_path.py）

1. 元问题（"你能帮我做什么"）→ 第 1 轮直答，0 工具调用，done：`grounded=False & fast_path=True & route='direct_meta' & quotes=[]`；
2. 本项目问题（"质保期在哪响应的"）+ 模型第 1 轮试图直答（分别覆盖 JSON `final` 与首轮纯文本裸答两种输出）→ **回弹 1 次** → 第 2 轮检索 → 正常 final，`grounded=True`；
3. 回弹后模型仍直答 → 放行不压制，`grounded=False & fast_path=True`；
4. 历史整理边界：有 `prior_history` 时问"把上一轮结果整理成表格"→ 不回弹直接放行；**空会话首问**"把投标文件质保和报价整理成表格"→ **不放水，触发回弹 1 次**；
5. 概念题灰区两条拆分：
   - 5a（不含信号词的通用概念题，如"质疑期限一般是几天"）→ 模型第 1 轮直答不弹回，直接放行（`grounded=False`）；
   - 5b（含信号词"质保"的通用概念题，如"软件项目质保期一般怎么设置"）→ 首轮弹回 1 次；若第 2 轮模型仍坚持直答，因 `MAX_UNGROUNDED_BOUNCE_PER_TURN = 1` 强制放行（`grounded=False`），绝不无限死弹；
6. 带图附件的首轮直答 & `max_rounds=1` 单轮边界 → 均不触发回弹；
7. `/api/qa/sessions/{id}/ask`、`/ask/stream` 与 `messages_json` 落库回放：`grounded=False & fast_path=True` 全链路透传不丢失；
8. `BaseException` 透传不受护栏影响 + `limit=7` 弹回后消耗 1 轮、最多再走 6 轮检索（`rounds_used` 语义不回归）。
