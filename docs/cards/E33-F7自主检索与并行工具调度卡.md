## 1. 现状诊断与兼顾 E21 契约的关键裁决

1. **单轮只能串行发 1 个工具（[core/bid_react_agent.py](file:///e:/agent/BidGuard-Agent/core/bid_react_agent.py) L1204–L1377）**：
   - 目前每轮 JSON 仅解析单一 `"action"` + `"action_input"`，典型双书核对问题（如同时查招标与投标“质保期”）必须串行消耗 2 轮大模型网关往返；
   - **并发线程安全实查隐患（[core/hybrid_retriever.py](file:///e:/agent/BidGuard-Agent/core/hybrid_retriever.py) L305–L347）**：按 `doc_sha` 读写 `data/cache/{doc_sha}.emb.npy` 时缺少互斥锁与原子写替，同文档多关键词同轮并行检索若触发向量混合检索会互相踩缓存文件。
2. **模型缺少剩余轮次与停滞空转感知（`L1374–L1377`）**：
   - 工具观察回灌仅带固定一句 `"请继续下一步或输出 action='final'"`，模型不知自身剩余预算，也无法感知连续多轮空检或重复命中同一原文窗口（如 02 包质保期案例反复命中湖州合同）。
3. **挡位上限未拉开 + `low=7` 必须保底兼容 E21 既有单测**：
   - [backend/schemas.py](file:///e:/agent/BidGuard-Agent/backend/schemas.py#L365) `QaAskRequest.max_rounds` 卡在 `default=7, ge=1, le=8`，[QaChatView.vue](file:///e:/agent/BidGuard-Agent/frontend/src/views/QaChatView.vue#L787) 发请求硬编码 `max_rounds: 7`，[core/bid_react_agent.py](file:///e:/agent/BidGuard-Agent/core/bid_react_agent.py#L71-L76) `_EFFORT_UPSTREAM_MAP` 三挡上限全写死为 `7`；
   - **关键兼容性核对（请架构侧复核）**：[tests/test_e21_qa_context_and_stream.py](file:///e:/agent/BidGuard-Agent/tests/test_e21_qa_context_and_stream.py#L137-L205) 明确断言 `_resolve_effort_and_rounds('low', 7) == ('low', 7)`，且未传 `max_rounds`、仅传 `reasoning_effort='low'` 时跑完 6 工具 + `final` 并断言 `res['rounds_used'] == 7`。若按原口头举例把 `low` 压成 `5` 会直接打爆 E21 两条既有门禁！因此本卡**保留 `low -> 7` 兼容 E21**，向上拉开梯次为 **`low: 7` / `medium: 8` / `high: 12`**（同步放宽 `QaAskRequest.max_rounds` 上限 `le=8 -> 12`）。

## 2. 改动清单（2 块核心 + 并发底座 + UI 文案与 `INTERFACE.md` 同步）

### 2.1 方向 A：并行工具调用（`actions` 批量协议 + 有界并发 + 底层线程卫生）

1. **向后兼容协议扩展（[core/bid_react_agent.py](file:///e:/agent/BidGuard-Agent/core/bid_react_agent.py)）**：
   - 更新 `_REACT_SYSTEM_PROMPT`：继续兼容旧单条 `{"thought", "action", "action_input"}`，同时开放批量并行格式：
     ```json
     {
       "thought": "同时检索招标文件要求与投标文件响应",
       "actions": [
         {"action": "search_tender", "action_input": "质保期"},
         {"action": "search_bid", "action_input": "质保期"}
       ]
     }
     ```
   - 新增归一化 helper `_extract_round_actions(parsed: dict)`:
     - 若含非空 `actions` 列表：严格限流 **`MAX_PARALLEL_ACTIONS_PER_ROUND = 4`**（超过 4 条截断保留前 4 条，防单轮上下文爆量）；
     - 若 `actions` 中同时混入 `'final'` 与真实工具：剥离 `'final'` 仅执行工具列表，避免跳过工具直接早退；仅当归一化后只剩 `'final'` 时按 `'final'` 分支收口；
     - 未传 `actions` 时保持原单 `"action"` + `"action_input"` 解析零变化。
2. **抽出共享分发器 + 有界线程池 + E30/E31 双铁律保底**：
   - 将原 `L1250–L1361` 的 `if/elif` 分支抽取为单一共享函数 `_dispatch_single_tool(...)`（消除重复代码，保留 **E31 单工具 `try/except Exception` 转 `observation.error` 自愈**）；
   - 本轮工具调用数 `>= 2` 时使用 `ThreadPoolExecutor(max_workers=min(4, len(tool_calls)))` 并发调用 `_dispatch_single_tool`，**严格按原列表下标顺序**汇总每条结果、提取 `collected_tool_quotes`；仅 1 条时就地顺序执行；
   - **线程安全清单（逐工具核验）**：
     - `search_tender` / `search_bid` / `locate_chapter` / `recalc_price` / `check_cert_expiry` / `search_attachment`：只读字符串与独立局部变量；
     - `client.embed()`：依赖 `LLMClient._lock` 保障用量统计线程安全；
     - `cite_regulation`：按次调用内部独立通过 `_get_active_session(None)` 创建并关闭 SQLite Session（遵循“法规库 SQLite Session 按次独立开”）；
     - **[core/hybrid_retriever.py](file:///e:/agent/BidGuard-Agent/core/hybrid_retriever.py) 缓存锁加固**：按 `doc_sha` 维护分段锁 `_CACHE_LOCKS`（由 `_CACHE_LOCKS_GUARD` 保护），且 `.emb.npy` 写入改为临时文件 + `os.replace()` 原子落盘，消除同文档多关键词同轮并行检索的缓存竞态；
   - **E30 并发取消保底**：在并发收集结果块显式捕获 `BaseException`，立即 `pool.shutdown(wait=False, cancel_futures=True)` 并原样上抛。
3. **步骤结构、回灌格式与 `rounds_used` 语义**：
   - `steps` 保持平铺 `list[dict]` 不变：同轮并发的 `k` 条子调用按提交下标依次生成 `step_item` 与 SSE `step` 帧（均标注同一思考回合号 `round = r_idx`，附带可选 `batch_index`（1-based）、`batch_size`）；
   - `rounds_used` 精确统计**大模型思考回合数**（例如 `7` 个思考回合每回合最多 `4` 次并行调用 = 最高 `28` 次工具查证）；
   - 回灌大模型时合并为结构化观察消息：
     `工具批量返回结果（本轮并行 {k} 项）：\n[1] search_tender(...) -> ...\n[2] search_bid(...) -> ...`

### 2.2 方向 B：自主检索深度（挡位上限解耦 + 预算与同源空转遥测 + 前端文案对齐）

1. **挡位天花板与请求上限解耦（[core/bid_react_agent.py](file:///e:/agent/BidGuard-Agent/core/bid_react_agent.py)、[backend/schemas.py](file:///e:/agent/BidGuard-Agent/backend/schemas.py)、[backend/routers/qa.py](file:///e:/agent/BidGuard-Agent/backend/routers/qa.py)）**：
   - 更新 `_EFFORT_UPSTREAM_MAP`：
     - `'low': ('low', 7)`（保留 `7` 保底，确保 E21 测试断言全绿）

     - `'max': ('max', 12)`

     - 当显式传入整数 `max_rounds`（如 `max_rounds=7` 或 `6`）时：有 `reasoning_effort` 取 `min(base_limit, gear_round_cap)`（于是 `('medium', 7)` 仍返回 `('high', 7)`、`('high', 7)` 仍返回 `('max', 7)`，100% 兼容 E21）；无 `reasoning_effort` 时取 `base_limit`；

   - [backend/schemas.py](file:///e:/agent/BidGuard-Agent/backend/schemas.py)：`QaAskRequest.max_rounds: Optional[int] = Field(default=None, ge=1, le=12)`（放宽 `le=8 -> 12`）；

2. **每轮确定性“预算 + 同源空转去重”遥测（[core/bid_react_agent.py](file:///e:/agent/BidGuard-Agent/core/bid_react_agent.py)）**：
   - 循环内维护已命中窗桶集合 `seen_hit_buckets: set[tuple[str, int]]`（对含 `'source'` 与 `'offset'` 的命中按 `(source, int(offset) // 120)` 归桶）及连续停滞计数 `stagnation_streak: int`：
     - 若本轮全部执行检索类工具（`search_tender` / `search_bid` / `locate_chapter` / `search_attachment`）且**全部空返回**，或所有命中桶**均已存在于 `seen_hit_buckets`** 中，则 `stagnation_streak += 1`；一旦检出任意新位置原文即归零（`recalc_price` / `check_cert_expiry` / `cite_regulation` 等非窗口检索回合保持计数不误惩罚）；
   - 每轮回灌给模型的 `user` 消息尾部附加确定性状态提示：
     - **预算进度**：`【思考回合进度：第 {r_idx}/{limit} 轮（剩余 {limit - r_idx} 轮可用）；如关键原文证据已齐备，请立即 action='final' 收口，无需凑满轮次。】`
     - **停滞去重**（仅当 `stagnation_streak >= 2` 时注入）：`【检索去重提示：已连续 {stagnation_streak} 轮空检或命中同一原文区间。若核心同义词仍仅命中无关历史合同/无新段落，请立即 action='final' 如实说明未检出及已命中片段归属，避免继续消耗轮次。】`
   - `_REACT_SYSTEM_PROMPT` 补充早停原则（拿齐关键原文立刻 `final`，不要为凑轮次无意义换词）；若跑满 `limit` 轮仍未 `final`，继续由 E32 强制收口轮兜底。
