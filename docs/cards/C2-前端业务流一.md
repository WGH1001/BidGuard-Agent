## 1. 任务背景

本卡把 8 个业务占位中的前 4 个换成真实页面——**C2 是全系统交互最重的一张卡**：
体检工作台（CheckDetailView）要消费 SSE 进度流、风险卡反馈、报价人工回填弹窗三大交互。

**视觉要求延续 C1 铁律**：沿用 C1 已确立的主题体系（`data-sidebar-theme` CSS 变量、severity 配色、
卡片风格），本卡页面与老项目蓝本**视觉上必须明显差异化**，蓝本只参考"数据怎么组织进页面"的机制。

## 3. CheckDetailView 交互规格（FRONTEND.md §2 checks 组 + §3 SSE）

1. **左栏任务台账**：`GET /api/checks` 分页列表（状态徽标、进度条、截标倒计时若有 open_date）；顶部"新建体检"按钮 → 上传弹窗（tender_file + bid_file 双文件、title、open_date、buyer_name、auto_run 勾选，multipart）。
2. **右栏详情**：选中任务 `GET /api/checks/{id}` → 六步流水线进度条（created→extracting→checking→grading→delivered，failed 红色）。
3. **SSE 实时进度**：`POST /{id}/run` 触发后连 `GET /{id}/stream`——按 FRONTEND.md §3 三事件分发；**重连后先收到终态帧必须幂等处理**；delivered 后自动拉 findings 刷新。
4. **风险卡列表**：`GET /{id}/findings`，按 severity 分组排序（error 红在上）；每卡显示 source_module 徽标（F1~F4）、code、clause_no、quote 原文（bid_quote 有值时双书对照展示）、message、suggestion、consequence；**采纳/驳回按钮**调 feedback 接口，状态徽标回显（accepted 绿勾 / rejected 灰叉）。
5. **报价人工回填弹窗**：`stats_json.price_status == 'NEED_MANUAL'` 时自动弹出（也可手动打开）——分项表格（名称/数量/单价/合价）+ 表合计 + 总价 + 大写 + 限价，金额全部字符串提交 `price-manual`；**返回 findings 非空时红色展示算术错误明细**（ITEM_ARITHMETIC 等），空则 toast"报价核验通过"。
6. **docx 页码为 null**：所有页码展示处 null 时显示"字符偏移 @N"（C1 的工具函数若已备好则复用，没有则新建 `src/utils/format.ts`）。

## 4. 实现铁律（违反即打回）

1. **契约唯一**：路径/入参/出参以 FRONTEND.md 为准；类型逐字段对齐；禁 any。
2. **金额展示**：两位小数 + 千分位；提交时字符串原样传（后端 Decimal）。
3. **SSE 用 C1 已就位的 `api/sse.ts` 封装**（fetch 流式），事件 progress/done/error 分发；页面离开时中断连接。
4. **上传大小/类型前端也预校验**（docx/pdf/txt，100MB），错误 toast 与后端错误码文案一致。
5. **visual 差异化**：页面版式、卡片布局、表格密度与蓝本明显不同；严禁出现合同/甲方/乙方/审查报告等旧项目残留词。
6. 蓝本（合并附件包内 5 个文件）只参考机制：任务列表分页怎么组织、风险卡数据怎么铺、SSE 状态怎么驱动进度条、docx 原文怎么展示。
7. **分批输出**（见 §5），每批先输出完整覆盖版 api/types.ts 与 api/index.ts 所在批次的文件，文件间严禁半截。

## 6. 验收标准（架构侧执行）

1. `npm run build` 零 TS 报错、零构建报错；
2. 真机冒烟：上传 mock 双书 → run → SSE 进度条走到 delivered → 风险卡出现 MISSING_RESPONSE/CERT_EXPIRED → 采纳回写 → 偏离表生成下载 → 雷达页"疑似"横幅；
3. 视觉与蓝本差异化人工核验；
4. 无旧项目残留词，全局 grep 自查。
