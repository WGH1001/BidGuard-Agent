# E24 · F7 标书专家多文件与图片附件问答卡（RapidOCR 与原生 VLM 双轨定稿）

> 状态：定稿待派发（2026-11-12）｜ 立卡：2026-11-11 ｜ 定稿：2026-11-12 ｜ 基线：commit `59b410e`（211 项全绿）
> 来源：用户需求——在 F7 标书专家追问中支持临时上传补充文档（补遗通知、澄清函、分项表等）及图片（营业执照、公章/签字页、截图等）联合问答；明确**不做**“流式输出途中插入对话（Harness Steering）”。

## 1. 设计原则与双轨策略

1. **通用文字底座（全模型 / 0-Token 默认可用）**：
   - `.docx/.pdf/.txt/.md` 经 `core/parser.py` 解析；`.png/.jpg/.jpeg` 经仓内离线 **RapidOCR** 提取全文并写入 `<file>.ocr.txt` 缓存；
   - 提取文本统一进入会话级附件检索池，供第 7 工具 `search_attachment` 检索并经 `quote_verifier.verify_quote()` 强制逐字溯源。
2. **原生 VLM 多模态增强（按需触发 + 单轮按选传图）**：
   - 仅当配置开启 `supports_vision=True` 且当轮提问 `attachment_ids` 显式携带图片附件时，在当前轮末尾 `user` 消息以 OpenAI 多模态数组 `[{"type": "text", ...}, {"type": "image_url", "image_url": {"url": "data:image/...;base64,..."}}]` 传图给 VLM 联合识图（补充判断印章、勾选框、手写批注、复杂无框截图）；
   - **历史会话消息严禁重复传图**（多轮 `history` 仅注入纯文本问答上下文，气泡回显附件引用胶囊）；
   - 若上游网关不支持看图并返回视觉拒参错误，自动剥离 `image_url`、触发单实例内存熔断并降级纯文本 + OCR 摘要重试，绝不死锁或误触发思考参数熔断。
3. **显式诚实降级与强溯源红线（铁律 3/4）**：
   - 文本 / OCR 命中原文必须过 `verify_quote()` 记录连续子串 `offset` 与 `attachment_id` / `attachment_name`；
   - 对无 OCR 文字或仅依靠 VLM 视觉判断出的图像结论，保留回答正文但引用强制标 `quote_verified=False` 并附降级说明，**绝不编造 `offset` 或伪造 `quote_verified=True`**；
   - 任何伪造或跨会话 `attachment_id` 一律拒收或清空。

## 2. 改动清单（按模块拆分）

### 2.1 `core/parser.py` · 附件专用低门槛解析与 VLM 缩图辅助（不改 `parse_document` 签名）

1. **保持既有契约不动**：`parse_document(file_path: str) -> ParsedDoc` 与常规双书体检的 `OCR_MIN_CHARS = 100` 校验保持原样零回归。
2. **新增 `parse_qa_attachment(file_path: str | Path) -> dict[str, Any]`**：
   - 返回结构包含：`text`（`str`）、`source_type`、`pages`、`is_image`（`bool`）、`ocr_chars`（`int`）、`has_text`（`bool`）、`image_width`（`Optional[int]`）、`image_height`（`Optional[int]`）；
   - 对 `.png/.jpg/.jpeg` 复用 RapidOCR 与 `.ocr.txt` 缓存，但**取消 `OCR_MIN_CHARS = 100` 硬报错限制**：即使短截图或纯公章页仅识别出 `0~99` 字也正常落盘返回（`has_text = ocr_chars > 0`），不抛 `ValueError`；
   - 对损坏或空内容的文档附件抛出可读 `ValueError`，由路由层映射 `HTTP 422 ATTACHMENT_PARSE_FAILED`。
3. **新增内存级 VLM 图片缩放辅助 `encode_image_for_vlm(file_path: str | Path, max_edge: int = 2048, target_bytes: int = 2 * 1024 * 1024) -> dict[str, Any]`**（**定稿拍板：置于 `core/llm_gateway.py`**——VLM 发送侧职责与网关同域；`core/parser.py` 保持纯解析职责单一，严禁塞入发送逻辑）：
   - 利用 [requirements.txt](../../requirements.txt) 已有 `PyMuPDF==2.1`，**不新增 `Pillow` 依赖**；新代码统一 `import pymupdf`（2.1 起 `import fitz` 别名已触发 FutureWarning 弃用告警；存量 `parser.py` 旧用法不动）；
   - 磁盘原图原样保留（保证 RapidOCR 清晰度）；仅在构造发送给 VLM 的内存 `data:image/...;base64,...` 时，对长边 `> 2048px` 或原始体积超出 `2 MB` 的图片等比缩图并重编码为 JPEG（`quality=85`），避免 10~20 MB 原图在 Base64 膨胀后触发上游 HTTP 413 或超时。

### 2.3 `backend/routers/qa.py` + `backend/schemas.py` · 附件上传、配额管控与级联清理

1. **上传校验与存储配额**（用户拍板定案）：
   - **支持扩展名**：`{'.docx', '.pdf', '.txt', '.md', '.png', '.jpg', '.jpeg'}`（非白名单返 `HTTP 422 UNSUPPORTED_FILE_TYPE`）；
   - **空文件拦截**：`0` 字节返 `HTTP 422 EMPTY_FILE`；
   - **单文件大小上限**：**20 MB**（`20 * 1024 * 1024` 字节，超限返 `HTTP 422 FILE_TOO_LARGE`）；
   - **单会话总配额**：累计附件个数上限 **10 个** 且总存储体积上限 **100 MB**（`100 * 1024 * 1024` 字节，超限返 `HTTP 422 ATTACHMENT_LIMIT_EXCEEDED`）；
   - **单轮追问传入图片上限**：`attachment_ids` 中选中的图片附件单轮最多 **4 张**（超限返 `HTTP 422 TOO_MANY_IMAGES_PER_TURN`）。
2. **落盘安全与元数据**：
   - 落盘目录固定为 `data/uploads/qa/{tenant_id}/{session_id}/{att_id}{ext}`，强制 `Path(filename).name` 与 `resolve().is_relative_to(...)` 防路径穿越；
   - 上传即执行 `parse_qa_attachment()`，将 `{attachment_id, filename, ext, size_bytes, is_image, ocr_chars, has_text, rel_path, uploaded_at}` 追加写入 `qa_sess.attachments_json`；
   - 读取全文与分页上下文时按需读取磁盘原文件或 `.ocr.txt` 缓存，不在 `QaSessionOut` 列表响应体回传大段全文。
3. **新增 / 改造端点（沿用 `qa.py` 主路由 + 别名惯例）**：
   - `POST /api/qa/sessions/{session_id}/attachments`（multipart `file: UploadFile`，返回 `QaAttachmentOut`）；
   - `DELETE /api/qa/sessions/{session_id}/attachments/{attachment_id}`（从 `attachments_json` 移除并同步删除硬盘原文件及 `.ocr.txt` 缓存）；
   - 改造 `DELETE /api/qa/sessions/{session_id}`：删库同时 `shutil.rmtree` 清理 `data/uploads/qa/{tenant_id}/{session_id}/` 整个目录（含原文件与 `.ocr.txt`）；
   - 改造 `POST /{session_id}/ask` 与 `POST /{session_id}/ask/stream`：校验 `body.attachment_ids` 每个 ID 均须存在于本会话 `attachments_json`（存在伪造/越权 ID 直接返 `HTTP 422 INVALID_ATTACHMENT_ID`），校验图片张数 ≤ 4，解析出运行时附件列表传入 `ask_bid_expert*`；用户消息入库保留 `attachment_ids` / 附件摘要供历史气泡回显。
4. **`backend/schemas.py` 契约扩展**：
   - 新增 `QaAttachmentOut`（`attachment_id`, `filename`, `ext`, `size_bytes`, `is_image`, `ocr_chars`, `has_text`, `uploaded_at`）；
   - `QaSessionOut` 新增 `attachments: list[QaAttachmentOut] = Field(default_factory=list)`；
   - `QaAskRequest` 新增 `attachment_ids: list[str] = Field(default_factory=list)`；
   - `QaQuoteOut` 新增 `attachment_id: Optional[str] = None` 与 `attachment_name: Optional[str] = None`。

### 2.4 `config/models.yaml` + `core/llm_gateway.py` + `backend/worker.py` + `backend/routers/model_config.py` · `supports_vision` 全链与拒图熔断

1. **`config/models.yaml`**：`models` 下可配置 `supports_vision: true/false`（缺省 `False`）。
2. **`core/llm_gateway.py`**：
   - `build_client_from_user_config(..., supports_vision: bool = False)` 向后兼容新增参数；`LLMClient` 维护 `self.supports_vision` 与单实例熔断 `_mark_vision_unsupported()`；
   - `LLMClient.chat()` 与 `chat_stream()` 兼容 `messages[].content` 为 `str` 或多模态 `list`；在流式估算 fallback `prompt_tokens` 时对 `image_url` block 只计固定图像开销占位或文本部分，严禁把 Base64 字符串长度直接 `// 2` 当作 token；
   - 新增 `_is_vision_reject(e: Exception) -> bool`（精准组合判定：`image_url` / `vision` / `multimodal` / `unsupported image` 等 + 拒绝/非法语义词，**严禁误伤 401/429/500 与既有 `_is_thinking_reject`**）及 `_strip_image_blocks(messages)`；开启 `supports_vision` 发送含图请求遇上游拒图时，剥离图片改为提示文本、触发 `_mark_vision_unsupported()` 后重试一次。
3. **`backend/worker.py`**：`resolve_effective_llm_client` 透传 `supports_vision=bool(getattr(cfg, 'supports_vision', False))`；调用前护航 `ensure_user_model_configs_columns`。
4. **`backend/routers/model_config.py` & `backend/schemas.py`**：`ModelConfigUpsertRequest` 与 `ModelConfigOut` 新增 `supports_vision: bool = False`，存取透传并回显。

### 2.5 `core/bid_react_agent.py` · 第 7 工具 `search_attachment` 与反幻觉溯源

1. **工具池扩至 7 工具**：
   - `ALLOWED_REACT_TOOLS` 在保持原 6 工具不变的基础上新增 `'search_attachment'`；
   - `ask_bid_expert` 与 `ask_bid_expert_stream` 新增可选形参 `attachments: Optional[list[dict[str, Any]]] = None`（默认值 `None` 保持老调用 100% 兼容）；
   - `search_attachment(keyword, attachment_id='', ...)` 在当前加载的附件文本池中检索并输出 `[{attachment_id, attachment_name, quote, offset, page, is_image, ocr_chars}]`；当指定或存在无字图片时明确提示图片基本信息（`ocr_chars=0`，请结合视觉观察或告知用户未提取出文本）。
2. **多模态当前轮注入 + 0-Token / 纯文本兼容**：
   - 仅当本轮 `attachments` 含图片且 `getattr(client, 'supports_vision', False)` 为 `True` 时，将缩图后的 `image_url` block 附到本轮末尾 `user` 消息；其余情况与历史 `prior_history` 均维持纯文本消息；
   - 0-Token 分支（`client is None`）同步检索 `search_attachment`，有 OCR 或文档文本命中时正常拼装结果与 `quotes`；若仅上传了无文字图片，则明确返回诚实提示，不编造图内信息。
3. **溯源核验扩展（`_verify_and_locate_quotes`）**：
   - 处理 `source == 'attachment'`：先按 `attachment_id`（次选精确 `attachment_name`）定位对应附件正文；
   - 若附件不存在（模型编造 `attachment_id` / 文件名），或引用文字未通过 `verify_quote()` 在该附件全文找到连续子串，强制清空或标 `quote_verified=False`（`offset=None`），绝不放过幻觉引文；
   - 对纯看图结论（附件为图片且无匹配原文），保留回答正文但引用保持 `quote_verified=False` 并填 `note='视觉识别结论（非文字全文精确子串）'`。
4. **ReAct JSON 解析容错与高频条款续检防截断（顺手修复实战吐 JSON 故障）**：
   - `_parse_llm_json()` 在严格 `json.loads()` 失败后自动降级用 `json.loads(..., strict=False)` 容错 JSON 字符串字面量中未转义的真实换行/制表符（如 `"action_input": "*\n*"`）；
   - `ask_bid_expert_stream` 在 `if not parsed:` 兜底前拦截：若 `raw_content` 含 `"action"` 且含 `"thought"`/`"action_input"` 工具调用特征，**严禁直接作为最终自然语言回答输出给用户**，改为向模型注入纠偏提示让其重发合法单条 JSON（至多消费剩余轮数；耗尽则输出友好可读摘要而非裸露 JSON）；
   - 为 `search_tender` / `search_bid` / `search_attachment` 与 `locate_chapter` 新增可选 `after_offset: int = 0` 参数（缺省 `0` 向后兼容原签名），允许模型越过前 5 处总则/说明命中继续检索第四章等后段正文中的高频 `*` / `★` 条款。
