## 1. 真标书实战排障问题清单与根因实锤

基于北交大 04 包（`安易—04包-工业物性数据应用开发平台.docx`）与 02 包（`安易—02包.docx`）真标书全流程运行中暴露的四类根因：

1. **问题 1（04 包前 3 条实质需求误报 `MISSING_RESPONSE`）**：`core/response_checker.py` `_locate_bid_window_for_req` 对短语/首句种子调用 `bid_text.find(...)` 首现即返，首现直接命中第 1–2 页目录行（`4.1. 工业物性数据知识库\t114`，`offset=1163/1182/1199`）；下游 LLM 从目录窗中看不到响应正文，正确判定漏应答，导致 `技术偏离表`（`offset=111278`）正面应答被埋没。同时第 4 条（`四、` 售后服务漏“上门现场安装调试 + 3天操作培训”）属真实负偏离，升级定位器后须严格保留对照。
2. **问题 2（02 包第 22 页湖州历史合同图片误报 `CONTRADICTION`）**：`安易—02包.docx` 第 22 页（`offset=60690..61150`）附有湖州历史业绩合同扫描图，经图片 OCR 后拼入 `parsed_doc.text`。F4 对 `五、验收标准` / `六、售后服务` 首现即命中该图片 OCR 区间（`采川专家评审方式验收`、`质保期为3年`），误将过往业绩合同当作本次投标响应。
3. **问题 3（Stage 1.5 图片 OCR 进度在全缓存或冷启动首帧静默）**：`backend/worker.py` L720 `_on_bid_ocr_progress(done_items, total_items, _cached_hits)` 在 `total_items <= 0` 或 `done_items <= 0` 时直接 `return`，导致本地命中数十张图片缓存时前端进度条完全无播报、冷启动第 1 张耗时期间空白等待。
4. **问题 4（F2 `04/02` 包《开标一览表》/《分项报价表》提取落空及弹窗硬编码假数据）**：
   - `_COL_TOTAL_PRICE_KEYS` 缺失单独的 `'合计'` 列名，导致 04/02 包 Table 2（`数量（单位） | 单价 | 合计`）整表跳过；
   - `Table 1`《开标一览表》上方存在 `2 开标一览表` + `项目名称/编号/包号` 两段且表头缺 `项目名称` 只有 `投标人名称`，`_classify_table_priority` 误降级为 `secondary`；
   - `Table 1` Row 0 `投标总价（大写/小写，单位：元）` 横向合并两列、数据行拆为 `人民币小写：| 470000` 与 `人民币大写：| 肆拾柒万元`（02 包为 `1395000` 与缺 `元整` 的 `壹佰叁拾玖万伍仟`），L1649–1690 仅读 `rows[1][bid_col]` 且对 `壹佰叁拾玖万伍仟` 无法捕获；
   - `PriceSandbox._normalize_upper` 对含 `元` 仅省 `整` 的 `肆拾柒万元` 未归一化；
   - 前端 `PriceManualDialog.vue` 硬编码 `400000.00`/`485500.00`/`肆拾捌万伍仟伍佰元整` 演示假数据，误导人工核对。

## 2. 四项落地改动明细

### 2.1 ① F4 定位器升级与 OCR 来源区间标注（`core/parser.py` & `core/response_checker.py`）
1. **`core/parser.py`**：`.docx` 解析组装 `text_parts` 时记录每段内嵌图片 OCR 文本的精确字符区间 `media_ocr_spans: list[dict[str, int]]`（`{'start', 'end', 'paragraph_index'}`），挂载到 `ParsedDoc.media_ocr_spans`（PDF/TXT/图片默认 `[]`，不删减全文，F3 证照与 F6 雷达照常消费）。
2. **`core/response_checker.py`**：
   - 扩窗至 `_BID_WIN_BEFORE=360` / `_BID_WIN_AFTER=600`；
   - 新增 `_is_toc_region`（跳过 `\t页码` / `...页码` 目录行，并防止无标点短邻行误杀正文句子）、`_is_in_media_ocr_or_historical_contract`（命中 `media_ocr_spans` 区间或按 OCR 边界隔离后的历史合同/审计附注启发式窗口）、`_score_bid_candidate_window` 与 `_find_best_valid_occurrence`（遍历全部出现位置，对《技术偏离表》/`我公司提供的产品完全满足`/`无偏离` 等正面响应窗口加分择优）；
   - `_build_direct_hit_result` 在仅命中小节短标题（`<35` 字）时顺延下一非空正文行（确保连续切片 100% 通过 `verify_quote`）；
   - 透传 `bid_media_ocr_spans` 至 `_locate_bid_window_for_req`（含 `bid_units`/逐行扫描/`hybrid_retrieve_windows`）及 `check_bid_self_contradictions`。

### 2.2 ② & ④ F2 确定性补齐、大写归一化边界与 LLM 表格坐标感知（`core/price_sandbox.py` & `core/price_extractor.py`）
1. **`core/price_sandbox.py`**：`_normalize_upper` 在 `"正"→"整"`、`"圆"→"元"` 后，对以 `'元'` 结尾省写 `'整'` 的金额（如 `肆拾柒万元`）补齐 `'整'`；连 `'元'` 都缺的不规范写法（如 `壹佰叁拾玖万伍仟`）与角分漏字（如 `壹元伍角叁`）不做补齐，继续由沙盒报 `UPPER_MISMATCH`。
2. **`core/price_extractor.py`**：
   - `_COL_TOTAL_PRICE_KEYS` 增补 `'合计'`；
   - `_iter_doc_tables_with_prev_heading` 改为保留表格上方最近 3 个非空段落（跨表清零），`_classify_table_priority` 增认 `'投标人名称'` / `'报价人名称'` / `'供应商名称'`；
   - `_extract_from_docx_tables` 兼容《开标一览表》横向合并表头 `bid_header_cols` 与多行 `人民币小写：` / `人民币大写：` 子标签行，在明确 `大写` 格回退匹配纯中文大写串 `_BARE_UPPER_CN_RE`；
   - 新增 `_collect_price_perception_payload` 与 `_llm_perceive_price_tables`（`extract_price_data` / `run_price_check` 新增可选 `client=None`）：仅当确定性提取落入 `NEED_MANUAL`（且无歧义预警）时启用 LLM 识别单元格/行坐标 `[T{ti}R{ri}C{ci}]` / `[L{li}]`，**严禁采信 LLM 自填数字**，由 Python 查验 `coord_map` 与 `verify_quote` 后回读原格，用 `_parse_money_str` / `_parse_qty_str` 转 `Decimal` 送入 `PriceSandbox`。

### 2.3 ③ Stage 1.5 OCR 进度播报与前端弹窗真实预填（`backend/worker.py` & 前端 3 文件）
1. **`backend/worker.py`**：
   - `_on_bid_ocr_progress` 当 `total_items <= 0 and _cached_hits > 0` 播报本地缓存秒级加载数量；当 `done_items <= 0 and total_items > 0` 立即播报 `0 / total_items` 冷启动起始帧；
   - `run_price_check(..., client=client)` 传入当前任务有效 `client`；
   - `stats_payload` 透出 `reference_bid_total`、`table_total`、`bid_total_upper`、`price_items`。
2. **前端（`types.ts` / `CheckDetailView.vue` / `PriceManualDialog.vue`）**：
   - `BidTaskStats` 与 `PriceManualDialog.vue` 接收上述真实提取字段并在打开弹窗/切换任务时同步预填，彻底清除 `400000.00`/`485500.00`/`肆拾捌万伍仟伍佰元整` 演示假数据。
