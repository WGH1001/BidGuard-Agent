# E26 · 招标所需证照清单确定性抽取与企业台账联动对账卡

> 状态：已验收（2026-11-12，227 项 pytest + `vue-tsc` + `vite build` 全绿，工作区待确认 commit）｜ 立卡：2026-11-12 ｜ 基线：E25 验收通过后推进
> 来源：用户 2026-11-12 提出"自动识别招标文件究竟需要提供哪些企业证照/产品认证/人员证书"，拍板采用 **先 A（F7 快捷追问）兜底，后 B（E26 单独立卡 0-Token 确定性提取 + 台账对账）** 方案。

## 1. 设计目标与工程约束

1. **纯确定性 0-Token 主通道（铁律 1）**：
   - 在 `core/tender_extractor.py` 新增 `extract_required_certificates(...)`，完全基于 F1 已解析文本、`qualification_hits`、`compliance_hits`、`marked_clauses`、`invalid_bid_clauses`、`scoring_tables`（及可选 `scoring_prose`）与统一双轨页码上下文提取招标方要求投标人提供的证照/资质清单；
   - 不新增 LLM 调用，不修改现有 `build_review_checklist()` 原有键结构（仅追加 `required_certificates` 键）。
2. **强制原文溯源与防误报护栏（铁律 3 / 铁律 4）**：
   - 每条提取出的证照需求均须附带原文 `quote`、经 `quote_verifier.verify_quote()` 核验后的 `quote_verified`、`offset`（字符偏移）以及通过 `resolve_unified_page` 计算的 `page`（无物理/印刷页码时诚实留 `None`，前端显示字符偏移）；
   - 显式拦截负面语境（如 `"投标文件中无需提供证明材料"`、`"特定资格要求：无"`、`"资格要求：无"`、`"采购人查询……无需投标人提供"`），宁缺毋滥，严禁将"免交说明"误报为必交证照；
   - 例外识别：即便条款在 `★/▲` 标记计数层面属于 `usage_note`（如 `"品目清单中带★产品只能选择具有国家确定的认证机构出具的、处于有效期之内的节能产品认证证书的产品进行报价"`），只因其文本明确规定强制产品认证要求，`extract_required_certificates` 仍可捕获其 `节能产品认证证书` 需求并标注真实来源。
3. **四分类 + 两级门槛清晰分层**：
   - `requirement_level`：`'mandatory'`（资格门槛/符合性/废标红线/政府强制采购） vs `'bonus'`（评分加分项/一般响应项）；
   - `category`：
     - `'enterprise_qualification'`（企业主体与资质：营业执照、财务报告/审计报告、完税/社保、信用承诺函、法定代表人证明/授权委托书、中小企业声明函、ISO 9001/14001/45001/27001/20000、CMMI、ITSS、CS、高新技术企业、软著、专利等）；
     - `'product_cert'`（产品及强制认证：节能产品认证证书、环境标志产品认证证书/十环、3C/CCC 强制认证、电信进网许可、信创互认/兼容性测试认证等）；
     - `'staff_cert'`（人员证书与职称：信息系统项目管理师、系统集成项目管理工程师、系统架构设计师、系统规划与管理师、软件评测师/设计师、网络/数据库工程师、建造师、高中级工程师职称等）；
     - `'bid_bond_or_ca'`（程序与电子开标凭证：CA 数字证书/电子签章、开标身份证原件等）。
4. **保守台账自动对账（租户严格隔离）**：
   - 在 `core/qualification_scanner.py` 新增 `match_required_certificates_with_ledger(required_certs, ledger_certs, reference_date=None)`：
     - 对每条需求规范化别名后保守匹配租户自身 `CompanyCertificate` 台账（如 `ISO 9001`/`ISO9001`/`质量管理体系`、`ISO 14001`、`ISO 45001`、`ISO 27001`、`软件著作权`/`软著`、`信创互认`、`信息系统项目管理师` 等，以及规范化连续核心词重叠）；
     - 参照 `open_date`（未识别时回退 `date.today()`）判定四态：`valid`（有效）/ `expiring_soon`（距到期 `<= warn_days`）/ `expired`（已过期）/ `not_in_ledger`（台账未收录）；多条匹配时择优状态保留最健康一条作主展示并回传 `matched_count`。

## 2. 改动清单

### 2.1 `core/` 确定性提取与台账匹配引擎
1. **`core/tender_extractor.py`**：
   - 新增标准证照规则表与 `extract_required_certificates(text, *, qualification_hits=None, compliance_hits=None, marked_clauses=None, invalid_bid_clauses=None, scoring_tables=None, scoring_prose=None, page_ctx=None) -> list[dict]`；
   - `build_review_checklist(file_path)` 在现有字典上追加 `'required_certificates'`。
2. **`core/qualification_scanner.py`**：
   - 新增 `_normalize_cert_key` / `match_required_certificates_with_ledger(required_certs, ledger_certs, reference_date=None) -> tuple[list[dict], dict]`，严格按 `reference_date`（`open_date` 优先，缺省回退 `today`）计算 `days_remaining` 与汇总 `cert_ledger_summary`。

### 2.2 `backend/` 契约与 `/api/extract` 联动
1. **`backend/schemas.py`**：
   - 新增 `MatchedLedgerCertOut`、`RequiredCertItemOut`、`CertLedgerSummaryOut`；
   - `ExtractChecklistOut` 追加 `required_certificates: list[RequiredCertItemOut] = Field(default_factory=list)` 与 `cert_ledger_summary: Optional[CertLedgerSummaryOut] = None`（全默认空/可空，100% 向后兼容）。
2. **`backend/routers/extract.py`**：
   - 当 LLM 抽取产出了段落型 `scoring_prose` 且非空时，补跑一次 0-Token `extract_required_certificates` 合并 `scoring_prose` 中的评分证书；
   - 按 `current_user.tenant_id` 查询 `CompanyCertificate` 台账，调用 `match_required_certificates_with_ledger(..., reference_date=res.get('open_date'))`，写入 `required_certificates` 与 `cert_ledger_summary`；审计明细追加 `required_certs_count`。

### 2.3 `frontend/` F1 视图第 ⑤ 页签与台账跳转
1. **`frontend/src/api/types.ts`**：
   - 同步新增 `MatchedLedgerCertOut`、`RequiredCertItemOut`、`CertLedgerSummaryOut` 与 `ExtractChecklistOut` 两个可选字段。
2. **`frontend/src/views/ExtractView.vue`**：
   - 概览区补充所需证照总数与门槛数量提示；
   - 新增页签 `⑤ 所需证照与台账对账 ({{ result.required_certificates?.length ?? 0 }})`：
     - 展示对账汇总条（参照日期来源 `开标日` 或 `今天`、台账已有效 / 临期预警 / 已过期 / 台账未收录统计）与 `"前往企业证照台账补录 →"` 按钮（跳 `/rules?tab=certs`）；
     - 筛选按钮：`全部` / `资格·废标门槛` / `评分加分项` / `台账缺口与异常`；
     - 卡片逐条展示：规范证照名、门槛等级徽标、四大类分类标签、台账对账四态徽标、命中章节与页码/字符偏移、`✓ 原文溯源通过` 校验标签、招标原文摘录，以及匹配到的台账证书详情（名称、编号、到期日、剩余天数、是否已传原件）。
3. **`frontend/src/views/RulesAndCertsView.vue`**：
   - `onMounted` 读取 `route.query.tab`（若为 `'certs'` / `'regulations'` / `'rules'` 自动切入对应页签）。

## 3. 验收标准与测试清单

新增 `tests/test_e26_required_certs_and_ledger.py`，覆盖：
1. **资格门槛 + 负面免交护栏**：识别营业执照、财务审计报告、完税社保、授权委托书等，同时确保 `"在信用中国网站查询……（投标文件中无需提供证明材料）"` 不产生误报；
2. **政府强制节能产品认证提取**：验证含 `"只能选择……处于有效期之内的节能产品认证证书"` 句式能精准落为 `mandatory` + `product_cert` 并过 `verify_quote` 溯源；
3. **评分细则企业资质与人员证书**：识别 `scoring_tables` / `scoring_prose` 中的 `ISO9001` / `ISO14001` / `ISO45001` / `软件著作权登记证书` / `信息系统项目管理师` 等并正确落为 `bonus`；
4. **台账四态对账与多租户隔离**：覆盖 `valid` / `expiring_soon` / `expired` / `not_in_ledger` 判定（以 `open_date` 为基准），以及多租户 A 上传调用 `/api/extract` 绝不匹配到租户 B 的台账证照；
5. **契约与旧缓存兼容性**：`/api/extract` 正常返回 `required_certificates` 与 `cert_ledger_summary`；全量 pytest + `vue-tsc --noEmit` + `vite build` 全绿通过。
