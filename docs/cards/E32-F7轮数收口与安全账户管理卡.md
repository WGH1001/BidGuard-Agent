## 2. 改动清单（3 块）

### 2.1 `core/bid_react_agent.py` 轮数耗尽强制收口轮

1. **追加 1 次强制收口调用（`ask_bid_expert_stream` L1340–1354）**：
   - 当 `1..limit` 轮循环均未返回 `action='final'` 且最后执行完工具时，向 `messages` 追加一条强制收口系统提示（`role: 'user'`）：
     - 明确告知**检索额度已用尽，严禁再调用任何检索工具**；
     - 指令模型严格依据前 `limit` 轮工具返回的 `observation` 原文窗口作答；
     - **防历史合同张冠李戴红线**：明确区分“招标文件要求”“我方针对本项目的投标响应”与“历史业绩/他人合同扫描件（如湖州项目等）”；若投标文件中仅命中其他历史合同而未检出针对本项目的对应响应，必须如实说明未检出本项目响应及存在漏应答/偏离风险，严禁张冠李戴或编造；
     - 要求仅输出 `{"thought": "...", "action": "final", "action_input": {"answer": "...", "quotes": [...]}}`，其中 `quotes` 必须 100% 逐字抄录自工具窗口。
   - 沿用 `reasoning_effort=norm_effort` + `TypeError` 降级兼容调用一次 `client.chat(...)`。
2. **解析、强制溯源与多级兜底**：
   - 若返回合法 JSON（支持 `action=='final'` 或直接包含 `'answer'` 键）且 `ans_text` 非空：对 `quotes` 强制走 `_verify_and_locate_quotes(...)` 逐字核验并补全页码/偏移定位，推送 `final` step 到 `steps`，再流式推送 `answer_delta` 与 `done`（保持 `rounds_used: limit`、`terminated_by_max_rounds: True`，附带 `forced_final: True`）；
   - 若模型返回非工具 JSON 的可读纯文本结论（`not _looks_like_unparsed_tool_json(raw_wrap)` 且非空）：直接采纳该结论正文并沿用 `collected_tool_quotes`，推送 `final` step、`answer_delta` 与 `done`（`forced_final: True`）；
   - 若收口调用触发 `Exception`（保留 `BaseException` 取消信号透传）或仍返回工具 JSON / 空串：安全降级保留原有模板提示 `fallback_ans` 与 `collected_tool_quotes`（`forced_final: False`），确保前 `limit` 轮已检索证据永不丢失。

### 2.3 轻量管理员用户与部门管理（`require_admin`）

1. **后端接口（[backend/schemas.py](file:///e:/agent/BidGuard-Agent/backend/schemas.py) + [backend/routers/auth.py](file:///e:/agent/BidGuard-Agent/backend/routers/auth.py)）**：
   - 扩展 `UserProfileOut` 增加 `tenant_name: Optional[str] = None`（`login` 与 `/me` 均顺带查询 `Tenant.name` 填入；`backend/auth.py` `get_current_user` 保持 `payload` 契约不动，在 `AuthUser` 中顺带填充 `tenant_name`）；
   - 新增管理员契约模型：`TenantOut`、`TenantCreateRequest`、`AdminUserOut`、`AdminUserCreateRequest`（`role: str = 'member'`）、`AdminUserUpdateRequest`（`role: Optional[str] = None`）、`AdminUserResetPasswordRequest`；
   - **`role` 强制白名单枚举校验**（必改 ①）：仅精确允许 `'admin'` 或 `'member'`，任何非法值（含 `'superadmin'`、`'admin '`、空串等）一律返回 `HTTP 422 INVALID_ROLE`，严禁写入脏值击穿权限模型；
   - 新增 6 个端点（全部 `Depends(require_admin)`，非 `admin` 一律 `403 FORBIDDEN`，全部写入 `AuditLog`）：
     - `GET /api/auth/tenants`：列出全部部门；
     - `POST /api/auth/tenants`：新增部门（重名 `409 TENANT_EXISTS`、空名 `422`，审计 `admin_create_tenant`）；
     - `GET /api/auth/users`：列出全部账号及所属 `tenant_name`、`role`、`is_active`、`last_login_at`；
     - `POST /api/auth/users`：新建账号（校验 `username` 非空且仅含字母数字/下划线/短横线/点、`username` 全局冲突 `409 USERNAME_EXISTS`、校验 `role ∈ {'admin','member'}` 否则 `422 INVALID_ROLE`、校验 `tenant_id` 存在 `404 TENANT_NOT_FOUND`、bcrypt 哈希、审计 `admin_create_user`）；
     - `PATCH /api/auth/users/{user_id}`：修改姓名 `display_name`、所属部门 `tenant_id`、角色 `role`（校验 `INVALID_ROLE`）、启停状态 `is_active`——**内置防自锁双护栏**（先检查若该操作会令系统最后 1 名活跃 `admin` 被禁用或降级则返回 `409 LAST_ADMIN_PROTECTED`；当存在 >=2 名活跃 `admin` 时管理员仍禁止对自己禁用或降级 `409 CANNOT_MODIFY_SELF`），审计 `admin_update_user`；
     - `POST /api/auth/users/{user_id}/reset-password`：管理员重置指定用户密码（校验长度 ≥6、bcrypt 更新，审计 `admin_reset_password`）。
2. **前端管理界面与路由鉴权**：

3. **管理员用户与部门管理闭环（含越权、非法 role 422 与防自锁双护栏）**：
   - 普通 `member` 调用 `/api/auth/users`、`/api/auth/tenants` 全系列端点一律 `403 FORBIDDEN`；
   - **非法 `role` 枚举拦截（必改 ①）**：创建/更新用户传入 `'superadmin'`、`'admin '` 或 `''` 一律返回 `422` 且 `detail['code'] == 'INVALID_ROLE'`；
   - **防自锁双护栏（必改 ②）**：系统仅剩 1 名活跃 `admin` 时禁用或降级该 `admin` 返回 `409 LAST_ADMIN_PROTECTED`；新建第 2 名 `admin` 后，原 `admin` 禁用/降级自己返回 `409 CANNOT_MODIFY_SELF`，同时可正常禁用/降级第 2 名 `admin`；
   - `admin` 新建部门 -> 跨部门新建商务经理账号 -> 该新账号登录返回正确 `tenant_name` -> 调换部门与角色 -> 管理员重置密码后旧密码拒登、新密码可登；
   - `admin` 禁用该账号后，该账号**既有 Bearer token 立即返回 `401 USER_DISABLED`**；再次启用后可重新登录；
   - 重名 `username` 返回 `409 USERNAME_EXISTS`，全部写操作均有对应 `AuditLog` 记录且不含任何密码明文或哈希。
