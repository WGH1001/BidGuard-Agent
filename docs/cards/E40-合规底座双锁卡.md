## 1. 核心目标

1. **全局脱敏唯一落点 = 模型网关**：新增 `core/privacy_sanitizer.py`，在 `core/llm_gateway.py` 的 `chat()` / `chat_stream()` / `embed()` **三个总出口统一挂载**（全系统所有 LLM/向量调用——F1 fallback / F3 受控语义鉴别 / F4 / F6 / F7 / F8 / E36 AI 复核——均走 LLMClient，一处封死、零逐模块改动）。**严禁在业务模块各自手挂脱敏**。
2. **原文件不动铁律**：上传落盘的 `.docx/.pdf` 原件保持逐字节不变——0-Token 确定性引擎（F2 算术 / F3 串名 / BM25 检索 / E5 批注锚点 / E37 Clean 定稿 / E36 SHA256 碰撞指纹）继续吃原文，位置与算术零漂移；脱敏只发生在**送 LLM 的文本**与**上传回显统计**。
3. **内网模型防外泄硬锁**：新增环境变量开关 `STRICT_INNER_MODEL_ONLY`（默认关闭，单测可控），开启后 `/api/model-config` 自定义配置**放行内网、仅禁公网**——内网 IP/内网白名单域与任意内网模型名照常可用，填公网地址（如 `open.bigmodel.cn`、`api.openai.com`）返回 `422 MODEL_HOST_FORBIDDEN`；同时禁用云端 `demo` 环境回退。

## 2. 技术设计明细

### §2.1 新模块 `core/privacy_sanitizer.py`
1. **两类确定性识别（纯正则 + 校验，0 Token，库模块静默）**：
   - **18 位居民身份证号**：含 GB 11643 校验位验证（校验失败不判为身份证，防误伤项目编号/单号），保留前 3 后 4 等长掩码（`310***********123X` 形态，掩码后字符数不变）；
   - **银行卡/对公账号**：12~25 位数字串，**允许含空格或连字符 4 位分组**（如 `6222 0210 0111 2223 334`），**必须带语境约束**（前后文命中 `银行|卡号|账号|开户行|对公|储蓄卡|借记卡` 等关键词）——严防误伤项目编号、招标编号、标准号（`GB/T ...`）、金额数字与电话号码；掩码**仅替换数字中间位**（保留前 4 后 4 与原分隔符，严格等长）；含 `*` 的已掩码串跳过以保证幂等。
2. **`sanitize_text(text) -> tuple[str, dict]`**：返回（脱敏文本, `{"id_masked": x, "bank_masked": y}` 统计）；**幂等**（已掩码形态不二次处理）；**等长掩码**保证后续任何字符偏移类消费方不受影响。
3. **`scan_document_text(text) -> dict`**：上传环节轻量化只读扫描（不修改文本，仅计数），供上传响应回显。

### §2.2 挂载 `core/llm_gateway.py`
1. `chat()` / `chat_stream()`：对 `messages` 中**仅 `text` 文本段**做 `sanitize_text`（E24 多模态 `image_url` 等 dict/list 结构原样保留不破坏），`tools`/`system` 文本一并覆盖；脱敏统计累加进现有线程安全用量结构（新增计数器，可观测）。
2. `embed()`：输入文本先 `sanitize_text` 再送向量。
3. 开关：环境变量 `PRIVACY_SANITIZE_ENABLED`（默认 `'1'` 开启；置 `'0'` 关闭用于对照测试）。
4. **已知行为（宁缺毋滥，写进验收预期）**：LLM 回引含掩码身份证/银行卡的原句时 `verify_quote` 判不匹配 → 走既有"清空摘录 + `quote_verified=False`"降级路径。验收时监控全量回归 `quote_verified=False` 率无异常抬升（身份证/银行卡号极少出现在评分响应引用中）。

### §2.3 上传回显（轻量，**零 OCR 硬规定**）
1. `backend/routers/checks.py` 体检文档上传、`backend/routers/extract.py`（`POST /api/extract`，`ExtractView.vue` 实际调用点）与 `backend/routers/qa.py` 附件上传：响应中追加 `privacy_stats`（`{"id_masked": x, "bank_masked": y}`，只读扫描计数）；
2. **性能硬规定**：上传受理阶段 `scan_document_text` **严禁触发同步 OCR**——仅对 `.docx` 文本段/表格与 `.pdf` 原生文本层执行 `ocr_images=False` 快速扫描（真实标书可达 40~50 MB，全图 OCR 会把毫秒级上传接口卡死成分钟级）；QA 图片附件与扫描件内容由后台 Stage 1.5 OCR 完成进入 `llm_gateway.py` 时照常统一脱敏兜底；
3. 前端回显落点：`CheckTaskList.vue`（体检创建提示）、`ExtractView.vue`（提取成功提示）与 `QaChatView.vue`（附件上传提示）追加"已识别并保护 X 处身份证号、Y 处银行账号"（Neutral 措辞，不展示具体号码）；`types.ts` 同步字段。**涉 `types.ts`：本卡必须串行实现，并行期间另一方停手该文件。**

### §2.4 `backend/routers/model_config.py` 内网锁定
1. 新增读取环境变量 `STRICT_INNER_MODEL_ONLY`（默认 `'0'` 关闭）与 `INNER_MODEL_EXTRA_HOSTS`（逗号分隔内网白名单域，可选）；
2. strict 开启时 `_validate_base_url` 升级判定：放行私网网段（`10.*` / `172.16~31.*` / `192.168.*`）与 `INNER_MODEL_EXTRA_HOSTS` 白名单域 + 现有 `localhost` 例外逻辑不变；公网域一律 `422 MODEL_HOST_FORBIDDEN`（提示"已锁定公司 inner 模型，仅允许内网网关"）；
3. strict 开启时禁用 `demo` 云端环境回退：`LLMClient` 解析 `default_env` 强制钉 `prod`，用户级公网自定义配置在 strict 下拒绝保存；存量公网配置由 `backend/worker.py::resolve_effective_llm_client` 调用时忽略并告警（落点实测在 worker.py L293）；
4. strict 开启时 `/model-config` 放行范围：私网网段（`10.*` / `172.16~31.*` / `192.168.*`）+ `models.yaml` 当前 `prod` 主机（`10.0.2.81`）+ `INNER_MODEL_EXTRA_HOSTS` 白名单域——内网任意网关 IP、模型名与内网 Key 100% 照常可用；
5. 现有校验行为在 strict=0 时**完全不变**（保护既有 317 项回归）。
