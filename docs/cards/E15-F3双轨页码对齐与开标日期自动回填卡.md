# E15 · F3 双轨页码对齐与开标日期自动回填卡

> 状态：已派发 Gemini（2026-11-09）｜ 立卡：2026-11-09 ｜ 基线：commit 314b630
> 来源：用户实测反馈——同一份 docx，F4 显示"第162页(印刷页150·估算)"，F3 只显示裸"字符偏移 @28880"，体验不一致

## 1. 背景

1. `BidFinding.page` 列只有 **F4** 在写库时赋值（E6 双轨页码链由 response_checker 算好 `bid_page` 透传）；**F3** findings 有 `quote_offset`（worker.py L408）但从不写 `page` → 前端 `formatPageOrOffset` 回退显示裸偏移。
2. worker.py L276-279 开标日期链：`config_json.open_date → rule_cfg.open_date → 硬编码 '2026-11-05'`——用户忘填时 F3 效期核验拿着历史示例日期默默计算，结论全歪且无任何提醒。

## 2. 改动清单

1. **F3 findings 接 E6 双轨页码链**（backend/worker.py F3 写库处，约 L402-458 两段）：
   - 流水线内对投标文件一次性计算页码索引：`build_docx_page_spans(bid_abs)`（E6 既有函数，core/parser.py）+ `offset_to_docx_page(offset, spans)`；
   - F3 每个 finding 写 `page=offset_to_docx_page(f3_item.get('offset'), spans)`；docx 无分页符时自然回退物理页估算，行为与 F4 完全一致（前端无需改动，formatPageOrOffset 已兼容）；
   - PDF 投标书走既有 build_pdf_page_spans 逻辑（若 F3 场景涉及），保持与 F4 同款。
2. **开标日期自动回填**（backend/worker.py 阶段 1 F1 解析完成后）：
   - 若 `config_json.open_date` 与 `rule_cfg.open_date` 均为空，用**确定性正则（0 Token）**从招标书解析文本提取开标/递交截止时间，支持形态：`开标时间[：:]?\s*2026年10月29日`、`提交投标文件截止时间[：:]?\s*2026年11月25日10:30:00`、数字间允许空白字符（参考架构侧验收脚本 output/_verify_wuhu_sim.py 中的正则写法）；
   - 提取成功 → 回填 `task.config_json['open_date']`（UTC now 更新）并随 SSE 帧广播"已自动识别开标日期：YYYY-MM-DD"；
   - 提取失败 → 保持现默认并追加一条 F3 `warning` finding：code=`OPEN_DATE_FALLBACK`，message 明示"未识别到开标日期，效期核验基于默认日期 YYYY-MM-DD，请人工核对"；
   - 用户手填值**永远优先**，绝不被自动回填覆盖。
3. **前端文案润色**（顺手活）：新建任务弹窗开标日期 label 追加"（留空则体检时自动从招标书识别）"；勾选框文案补"不勾选则仅创建任务，稍后可手动启动"。

## 3. 验收标准

1. pytest 新增：① 构造含"开标时间：2026年11月25日 10:30"的招标书 + 空 open_date 任务 → 跑流水线后 config_json.open_date == '2026-11-25'；② 手填 open_date 的任务不被覆盖；③ F3 finding（构造 SOCIAL_MONTH_MISSING 场景）的 page 字段非空且与 offset 同页；
2. 全量 pytest（基线 149 项 + 新增）零回归全绿；
3. 前端走查：F3 卡片页码显示"第N页(...)"与 F4 同款；新建弹窗文案更新。
