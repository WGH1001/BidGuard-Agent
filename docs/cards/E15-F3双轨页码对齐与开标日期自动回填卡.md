> 来源补充：用户指出"单价/数量/合价三数字集中出现在报价表同一行，F2 凭什么做不了页码"——原"F2 不改"判断作废，锚点页码方案并入本卡

> 补正（2026-11-09，Antigravity 交叉审查实锤）：① PDF 双格式分支原卡文含糊，已明确复用 response_checker 既有双轨上下文函数；② F2 锚点反查补防"前文重名污染"护栏；③ worker 自定义红线扫描（L443-465）算了 pos 却漏传 page，顺手补齐

## 1. 背景

1. `BidFinding.page` 列只有 **F4** 在写库时赋值（E6 双轨页码链由 response_checker 算好 `bid_page` 透传）；**F3** findings 有 `quote_offset`（worker.py L408）但从不写 `page` → 前端 `formatPageOrOffset` 回退显示裸偏移。
2. worker.py L276-279 开标日期链：`config_json.open_date → rule_cfg.open_date → 硬编码 '2026-11-05'`——用户忘填时 F3 效期核验拿着历史示例日期默默计算，结论全歪且无任何提醒。

## 2. 改动清单

1. **统一页码上下文（本卡所有 page 计算的唯一入口）**（backend/worker.py）：
   - 流水线内对投标文件一次性构建**双格式自适应**页码上下文：直接复用 core/response_checker.py L140/L155 既有函数 `_build_unified_page_context(bid_abs)`（自动区分 .pdf/.docx，非两种格式返回 kind='none'）+ `_resolve_unified_page(offset, ctx)`（返回 (physical_or_pdf_page, footer_page, is_docx_page)）——**严禁在 worker 里自己写 if/else 分支或直接单调 docx 函数**（PDF 标书直接调 build_docx_page_spans 会报错，Antigravity 交叉审查实锤的第一处漏洞）；
   - 若这两个函数当前为 response_checker 私有（下划线开头），允许将其提升为公共名或在 response_checker 内新增薄公共包装后从 worker 导入（不复制粘贴实现，单一事实源）；core/parser.py 只读调用严禁改动；
   - F3 每个 finding 写 `page=_resolve_unified_page(f3_item.get('offset'), ctx)` 的物理页；docx 无分页符时自然回退物理页估算，行为与 F4 完全一致（前端无需改动，formatPageOrOffset 已兼容）。
2. **开标日期自动回填**（backend/worker.py 阶段 1 F1 解析完成后）：
   - 若 `config_json.open_date` 与 `rule_cfg.open_date` 均为空，用**确定性正则（0 Token）**从招标书解析文本提取开标/递交截止时间，支持形态：`开标时间[：:]?\s*2026年10月29日`、`提交投标文件截止时间[：:]?\s*2026年11月25日10:30:00`、数字间允许空白字符（参考架构侧验收脚本 output/_verify_wuhu_sim.py 中的正则写法）；
   - 提取成功 → 回填 `task.config_json['open_date']`（UTC now 更新）并随 SSE 帧广播"已自动识别开标日期：YYYY-MM-DD"；
   - 提取失败 → 保持现默认并追加一条 F3 `warning` finding：code=`OPEN_DATE_FALLBACK`，message 明示"未识别到开标日期，效期核验基于默认日期 YYYY-MM-DD，请人工核对"；
   - 用户手填值**永远优先**，绝不被自动回填覆盖。
3. **F2 发现锚点页码定位（原 E17 并入，core/price_extractor.py + worker.py）**：
   - price_extractor findings 补 `anchor_text` 字段：单行发现（ITEM_ARITHMETIC 类）锚该行分项名称（首选）或"名称+金额"组合串；表级发现（TOTAL_MISMATCH / CAP_EXCEEDED）锚开标一览表总价行文本；AMBIGUOUS_BID_TOTAL / CROSS_TABLE_BID_WARNING 锚歧义金额首次出现的行；无稳定锚文本的 finding 诚实缺省不输出；
   - worker F2 写库处：对带 anchor_text 的 finding 在 bid_parsed.text 反查 offset，**必须带"防前文重名污染"护栏**（Antigravity 交叉审查实锤的第二处漏洞——分项名称如"系统运维服务""培训服务"常在前文技术方案章节多次出现，裸 find() 会错锚到第 15 页而非报价表页）。降级匹配链：
     a. 首选：锚文本用特征串 `f"{name} {unit_price}"`（分项名称+金额同现，报价表行独有特征）在全文搜首次出现；
     b. 次选：特征串搜不到 → 在**报价相关章节区域**内搜裸名称（区域锚定法：以开标一览表/分项报价表已识别的 offset 为中心 ±3000 字符窗口；该 offset 取自 price_extractor detail_table_records 既有信息，无需新算）；
     c. 末选：仍搜不到 → 保持 quote=None/page=None 诚实回退"—"，与 F4 五级降级链同精神，严禁硬造；
   - 写入 quote=实际命中的原文子串（须 quote_verified=True）、quote_offset、page=_resolve_unified_page(offset, ctx)；
   - 前端零改动（formatPageOrOffset 已兼容三态）；
4. **自定义红线扫描顺手补 page**（backend/worker.py L443-465 部门自定义关键词红线扫描）：该处已算出 pos（quote_offset 已写）但漏传 page——Antigravity 交叉审查实锤的第三处漏洞。补 `page=_resolve_unified_page(pos, ctx)`，其余行为一字不动；
5. **前端文案润色**（顺手活）：新建任务弹窗开标日期 label 追加"（留空则体检时自动从招标书识别）"；勾选框文案补"不勾选则仅创建任务，稍后可手动启动"。

## 3. 验收标准

1. pytest 新增：① 构造含"开标时间：2026年11月25日 10:30"的招标书 + 空 open_date 任务 → 跑流水线后 config_json.open_date == '2026-11-25'；② 手填 open_date 的任务不被覆盖；③ F3 finding（构造 SOCIAL_MONTH_MISSING 场景）的 page 字段非空且与 offset 同页；
2. F2 锚点用例：① 构造含 ITEM_ARITHMETIC 的报价表 → 该 finding quote 为分项名称原文子串、page 非空；② **前文重名污染用例**：构造"培训服务"在技术方案章节（前文）与报价表（后文）均出现、报价表行金额算术错误 → 断言锚点 offset 命中报价表区域而非前文首次出现；③ 锚文本被合并单元格拆散形态 → 诚实回退无 page 零报错；④ 芜湖无为真实语料复测：AMBIGUOUS_BID_TOTAL 等带 page 或诚实回退（断言不硬造）；
3. PDF 用例：构造 .pdf 投标文件任务 → F3/F2 finding 的 page 由 build_pdf_page_spans 链路计算非空（或该 PDF 无法算页时诚实回退），断言 docx 与 pdf 两格式均零报错；
4. 红线扫描用例：构造命中自定义红线词的任务 → CUSTOM_REDLINE_HIT finding 的 page 非空且与 quote_offset 同页；
5. 全量 pytest（基线 151 项 + 新增）零回归全绿；
6. 前端走查：F3/F2 卡片页码显示"第N页(...)"与 F4 同款且点击可跳转；新建弹窗文案更新。
